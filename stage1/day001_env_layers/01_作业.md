## 第 2 题 · 亲手制造一次「包消失」

**做什么**：装一个 lock 里没有的包，然后让 `uv sync` 处理它。

```bash
uv pip install cowsay
uv run python -c "import cowsay; print(cowsay.__version__)"
uv sync
uv run python -c "import cowsay"
```

**验收结果**：

- 第 2 条命令打印 `6.1`
- 第 3 条命令的输出里必须有这两行：
  ```
  Uninstalled 1 package in ...
   - cowsay==6.1
  ```
- 第 4 条命令报错，最后一行是：
  ```
  ModuleNotFoundError: No module named 'cowsay'
  ```

**如果你看到的不是这样**：说明你的 `pyproject.toml` 里被人加过 `cowsay`
（那就不会消失了）。用 `grep cowsay pyproject.toml` 确认，然后换一个包名重做。

## 第 3 题 · 两种保住它的办法，各自验证一次

**做什么**：

```bash
# 办法 A：临时豁免
uv pip install cowsay
uv sync --inexact
uv run python -c "import cowsay; print('A 活下来了')"

# 办法 B：写进 lock
uv add --dev cowsay
uv sync
uv run python -c "import cowsay; print('B 活下来了')"
```

**验收结果**：

- 办法 A 后：`uv sync --inexact` 只报 `Checked 106 packages`，**没有** `Uninstalled` 行；import 成功
- 办法 B 后：普通 `uv sync` 也不删它了，因为 lock 里现在有它；import 成功
- 两者差别的关键验证：`grep cowsay pyproject.toml` —— 办法 A 后**无输出**，办法 B 后有
  `"cowsay>=6.1",` 这一行

**做完必须清理**（否则仓库被污染）：

```bash
uv remove --dev cowsay
uv export --no-hashes --all-groups -o requirements.txt
uv run pytest -q          # 必须回到 7 passed
```

`check.py` 会检查这一步有没有做干净。

## 第 4 题 · 费曼任务：写给只会 npm 的同事

**做什么**：不超过 6 行，把本仓库的东西对应到 Node 世界。至少覆盖这 6 组：
声明文件 / 锁文件 / 安装目录 / 精确复现命令 / 加一个依赖 / 在环境里跑命令。

**验收结果**——对照检查，缺一条就是没过关：

1. `pyproject.toml` ↔ `package.json`
2. `uv.lock` ↔ `package-lock.json`
3. `.venv/` ↔ `node_modules/`
4. `uv sync` ↔ `npm ci`（不是 `npm install`——`npm ci` 才会删掉多余的东西）
5. `uv add <pkg>` ↔ `npm install <pkg> --save`
6. `uv run <cmd>` ↔ `npx <cmd>`

第 4 条是这题的陷阱：多数人会对到 `npm install`。区别是 `npm ci` 严格按 lock 装且清空多余，
`uv sync` 的行为跟它一致；`npm install` 会改 lock，而 `uv sync` 不会。

**自测**：把你写的 6 行给一个前端同事看，问他「怎么在新机器上复现这个环境」。
如果他答 `npm ci` 的等价物（`uv sync`）而不是 `pip install`，你讲清楚了。

## 第 6 题 · 证明 `requirements.txt` 是产物不是输入

**做什么**：

```bash
# 1. 手动加一行不存在的包
echo "this-package-does-not-exist==1.0" >> requirements.txt

# 2. 让 uv 同步环境
uv sync

# 3. 看环境有没有变
uv pip freeze | wc -l
uv run pytest -q
```

**验收结果**：

- `uv sync` 输出里**不出现任何错误**，也**不提到** `this-package-does-not-exist`
  ——它压根没读那个文件
- 第 3 步仍是 `106`
- 第 4 步仍是 `7 passed`
- `grep this-package requirements.txt` 仍能搜到那一行（你的改动还在，但毫无作用）

**这就是「静默失效」**：没有任何报错，你以为改了环境，其实什么都没发生。

**做完必须恢复**：

```bash
uv export --no-hashes --all-groups -o requirements.txt
grep -c this-package requirements.txt   # 必须无输出（退出码 1）
```
