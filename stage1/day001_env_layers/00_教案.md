# Day 1 · 你的环境到底由几层组成

> 原计划这一天是「安装 Python 3.10+、虚拟环境、pip」。这件事在本仓库已经完成，
> 而且完成得比计划更严格：Python 钉在 `>=3.13,<3.14`，包由 `uv` 管，不是 pip。
> 所以本日改成**环境体检日**——把已经存在的东西搞懂，比再装一遍有用。

---

## 今日问题

昨天你问过一件事：「可以有 pip 和 requirements.txt 么，它们和 uv 冲突么」。

当时我们做了个实验：往 `.venv` 里装了 `cowsay`，然后跑 `uv sync`，它**被删了**。
输出是 `Uninstalled 1 package - cowsay==6.1`，再 `import cowsay` 就是
`ModuleNotFoundError: No module named 'cowsay'`。

今天要回答的是：**为什么？谁有权决定 `.venv` 里有什么？**

这个问题不搞清楚，接下来 155 天你会反复踩它——每次装个新包，过几天发现不见了，
然后怀疑是 uv 坏了、或者怀疑自己记错了。

---

## 学习目的

分清三层，并且能用本仓库的真实数字说出每层有多少东西：

1. `pyproject.toml` —— **你想要的**（8 个运行依赖 + 2 个开发依赖）
2. `uv.lock` —— **解析出来的**（109 个包，含平台分支）
3. `.venv/` —— **磁盘上真有的**（106 个包，372 MB）

学完你应该能在 30 秒内回答「我的环境为什么是这个样子」，
并且知道环境出问题时**先看哪一层**。

---

## 学习内容

### 一、三层各管什么

`pyproject.toml` 里写的是**范围**，不是版本：

```toml
dependencies = [
    "chromadb>=1.5.9",
    "fastapi>=0.141.1",
    "httpx>=0.28.1",
    "langgraph>=1.2.11,<2.0",
    "openai>=3.8.0",
    "pydantic>=2.13.5",
    "pydantic-settings>=2.15.0",
    "uvicorn[standard]>=0.52.4",
]
```

8 行。但你的 `.venv` 里有 106 个包。中间那 98 个是谁决定的？
是 `uv.lock`——它把「我要 fastapi>=0.141.1」解析成「fastapi 0.141.1 需要 starlette 1.6.0，
starlette 1.6.0 需要 anyio 4.15.0……」的完整链条，并且**把每个版本钉死**。

所以三层的关系是：你写范围 → uv 解析成精确版本 → 装到磁盘。

`httpx` 那一行是个刚发生的真例子：它本来就在 `.venv` 里（`langsmith` 拖进来的传递依赖），
今天把它显式写进 `pyproject.toml` 之后，**三层数字一个都没变**——Resolved 仍是 109、
实装仍是 106。变的只有「谁为它负责」：以前它靠 langsmith 活着，`uv remove langsmith`
它就会跟着蒸发；现在它是你自己声明的，谁也带不走它。

### 二、`uv sync` 的语义：让第三层精确等于第二层

这句话是今天最重要的结论。`uv sync` 不是「把缺的装上」，而是
**「让 `.venv` 变成 `uv.lock` 的样子，多出来的删掉」**。

`cowsay` 被删就是这条规则的直接结果：它不在 lock 里，所以它是「多出来的」。

昨天的 `pip` 也是同样命运——被删了两次。最后解决的办法不是每次加 `--inexact`，
而是 `uv add --dev pip`，**把 pip 写进 lock**。进了 lock 的东西，`uv sync` 就不动它了。

这就是「谁有权决定」的答案：**只有 `uv.lock` 有权**。

### 三、为什么 109、108、106 是三个不同的数字

这是本仓库的真实数据，不是编的：

- `uv sync` 报 `Resolved 109 packages` —— 解析图里有 109 个节点，其中一个是本项目自己
  （`ai-agent-learning`，它是 virtual project，不安装自身）
- `requirements.txt` 里列出 108 个 —— 导出时去掉了项目自身
- `uv pip freeze` 数出来 106 个 —— 本机真正装上的

差的两个是**平台标记不匹配**，你在 `requirements.txt` 里能亲眼看到：

```
colorama==0.4.6 ; os_name == 'nt' or sys_platform == 'win32'
httpx2-jsfetch==1.0 ; sys_platform == 'emscripten'
```

`colorama` 是 Windows 终端颜色支持，你在 macOS 上不需要；
`httpx2-jsfetch` 是浏览器 WASM 环境用的。lock 是**跨平台**的，
所以它把两个平台的分支都记下来了，安装时按你的机器挑。

这条知识有实际用途：以后你在 Windows 同事机器上跑同一份 lock，
装出来的是 107 个包（多一个 colorama），不是环境坏了。

### 四、`requirements.txt` 是产物，不是输入

它由这条命令生成：

```bash
uv export --no-hashes --all-groups -o requirements.txt
```

**手改它对 `uv sync` 完全无效**——`uv sync` 只读 `pyproject.toml` 和 `uv.lock`，
不会提醒你两者对不上。它的唯一用途是给没有 `uv` 的人和 CI：
`pip install -r requirements.txt`（本机验证过：对空 venv dry-run 能解析出全部 106 个）。
