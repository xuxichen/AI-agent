## 今日问题

同一个文件里，两条路由，都在 `127.0.0.1:8714` 上跑着（第四节会带你建）：

```python
@app.get("/bad/{bid}")
def bad_by_id(bid: int):
    return {"handler": "bad_by_id", "bid": bid}


@app.get("/bad/me")
def bad_me():
    return {"handler": "bad_me"}
```

真跑结果：

```
$ curl -s -w ' [%{http_code}]' http://127.0.0.1:8714/bad/7
{"handler":"bad_by_id","bid":7} [200]

$ curl -s -w ' [%{http_code}]' http://127.0.0.1:8714/bad/me
{"detail":[{"type":"int_parsing","loc":["path","bid"],"msg":"Input should be a valid integer, unable to parse string as an integer","input":"me"}]} [422]
```

`/bad/me` 这个路由**确实定义了**，而且打开 `http://127.0.0.1:8714/openapi.json` 能看见它。
但请求根本没进 `bad_me()`——它被上面那条 `/bad/{bid}` 截住了，
然后因为 `"me"` 转不成 `int` 而报 422。

**问题：为什么文档里有它，请求却进不去？以及——把这两条 `@app.get` 的顺序换一下会发生什么？**

第四节回答，答案不在「谁更精确」上。

## 一、把服务起起来：`app:app` 里第二个 `app` 是什么

### ① 先确认包在哪一层（四分钟，终端 A）

这一步不写代码，只是把 Day 1 那三层摸一遍。在**仓库根**：

```bash
cd ~/Desktop/DELECTED/AI-agent
which uvicorn
```

真跑：

```
which 的退出码 = 1
```

什么都没印，退出码 1——**你的 shell 里没有一个叫 `uvicorn` 的命令**。同一条命令前面加 `uv run`：

```bash
uv run which uvicorn
uv run python -c "import sys; print(sys.executable)"
uv run python -c "import fastapi, uvicorn, pydantic; print(fastapi.__version__, uvicorn.__version__, pydantic.__version__)"
```

真跑：

```

/Users/admin/Desktop/DELECTED/AI-agent/.venv/bin/python3
0.141.1 0.52.4 2.13.5
```

**对上**：`uv run` 干的事，就是把 `.venv/bin` 临时摆到你 PATH 的最前面。
所以今天每条命令都得带 `uv run`——不带，`uvicorn` 就不存在。
这三个版本号你机器上应该一模一样（Day 1 用 `uv.lock` 钉死了）。

### ② 建文件（终端 A）

```bash
cd stage1/day004_fastapi_basics
mkdir -p code/python
cat > code/python/01_first_app.py <<'PY'
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def read_root():
    return {"service": "day004", "status": "ok"}
PY
```

四样东西，全部是你见过的形状：

| 这一行 | 是什么 | 哪一天见过的 |
|---|---|---|
| `from fastapi import FastAPI` | 从包里拿一个**类**出来 | Day 1（`import`） |
| `app = FastAPI()` | 把它实例化，名字**随便你叫**，叫 `x` 也行 | Day 2 的类那一节 |
| `@app.get("/")` | 装饰器：把下面的函数**登记**到 `app` 上 | Day 2 的装饰器 |
| `def read_root()` → `return {…}` | 普通函数，返回一个 dict | Day 3 第十一节 |

**今天一个新语法都没有。** 新的只有「dict 会被换成 JSON」这一件事，那是 FastAPI 干的，不是你写的。

对照你的 JS：

```js
// Express 的等价写法
app.get("/", (req, res) => res.json({ service: "day004", status: "ok" }));
```

区别只有一处：Express 要你自己喊 `res.json(...)`，FastAPI 是**你 `return` 一个 dict，它替你做**。

### ③ 终端 A 起服务

```bash
cd code/python
uv run uvicorn 01_first_app:app --port 8711
```

`01_first_app:app` 这一段是今天唯一的坑，先拆开：

- 冒号**左边** `01_first_app`：模块名，等于「当前目录下那个 `01_first_app.py`」。
- 冒号**右边** `app`：**那个文件里的变量名**，就是上面 `app = FastAPI()` 建的实例。

所以 `app:app` 读作「文件 `app.py` 里那个叫 `app` 的变量」。两个 `app` 毫无关系，只是碰巧同名——
你的文件叫 `01_first_app.py`，就得写 `01_first_app:app`；
如果你把变量改名成 `x = FastAPI()`，命令就得改成 `01_first_app:x`。

启动后 terminal A 出现（进程号你会不同）：

```
INFO:     Started server process [47689]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8711 (Press CTRL+C to quit)
```

**这四行之后，终端 A 就再也不返回提示符了。这是正常的**——它在听 8711 端口。

> 顺序上有个可能跟你不同的地方：上面是**后**印 `Uvicorn running` 那一行。
> 第八节加了 `--reload` 之后，那一行会**跑到了最前面**。
> 所以这一节你只核对「四行都在」，不核对顺序。

### ④ 终端 B：先猜再 curl

**先猜**：下面三条，你猜各自的状态码和正文。写下来再打。

```bash
curl -s -w ' [%{http_code}]\n' http://127.0.0.1:8711/
curl -s -w ' [%{http_code}]\n' http://127.0.0.1:8711/nope
curl -s -D - -o /dev/null http://127.0.0.1:8711/docs
```

（`-s` 别说话，`-w ' [%{http_code}]'` 在响应后面补一个状态码，`-D -` 把响应头打到屏幕上。）

真跑：

```
{"service":"day004","status":"ok"} [200]
{"detail":"Not Found"} [404]
HTTP/1.1 200 OK
date: Wed, 09 Sep 2026 02:44:32 GMT
server: uvicorn
content-length: 1006
content-type: text/html; charset=utf-8
```

同时终端 A 多出三行（端口号跟你不同）：

```
INFO:     127.0.0.1:53774 - "GET /docs HTTP/1.1" 200 OK
INFO:     127.0.0.1:53775 - "GET /openapi.json HTTP/1.1" 200 OK
```

> 上面这两行是我单独打 `/docs` 和 `/openapi.json` 时抓的。
> 你这三条 curl 打下去，A 里印的是 `/`、`/nope`、`/docs` 三条，形状一样：
> `INFO:  客户端端口 - "方法 路径 HTTP/1.1" 状态码 原因短语`。

**再用浏览器打开** `http://127.0.0.1:8711/docs`。
那是一个能点着发请求的页面（Swagger UI）。`/docs` 返回的是 HTML，不是 JSON，
所以它的内容类型是 `text/html; charset=utf-8`——这条**不是 FastAPI 猜的，是它写死的**。

### ⑤ 对上

**第 1 条 `[200]`**：`return {"service": "day004", "status": "ok"}` 一字不差地变成了 JSON。
键和值都在，但**双引号里的空格没了**——`"service": "day004"` 变成 `"service":"day004"`。
那是 JSON 序列化的正常表现，不是你写错了。

**第 2 条 `[404]`：这一条最重要。**
你没注册过 `/nope`，但**程序没崩**，终端 A 也没有红字。
FastAPI 替你回了一句 `{"detail":"Not Found"}`，然后把请求继续接着。
先记住这个形状，第七节我会**故意违背它**，让你看看「明明该 404 却回了 200」有多难查。

**第 3 条 `[200]` + HTML**：这条路由你**一行都没写**。
`/docs`、`/openapi.json`、`/redoc` 是 `FastAPI()` 这个对象自带的。
`content-length: 1006` 那个页面只有 1KB，因为它只引了一个 CDN 上的样式表——
**这意味着 `/docs` 打不开通常是你的网络到不了 jsdelivr，不是服务坏了**。
服务本身还是好的：`curl http://127.0.0.1:8711/` 照样回 200。

**终端 A 里那个 `127.0.0.1:53774`**：那是 **curl 那一侧**随手占的端口号，每打一条换一个。
它不是你的服务端口。别去核对它。

### 收尾：Ctrl+C 关掉服务

终端 A 按 `Ctrl+C`，会多出（**没有** `Finished server process` 那行的话，说明它是被硬中断的）：

```
INFO:     Shutting down
INFO:     Waiting for application shutdown.
INFO:     Application shutdown complete.
INFO:     Finished server process [47689]
```

**每一节结束后都这样关服务再进下一节。** 不关就换端口也能跑，但你会开始分不清哪条回显是哪个文件给的。

### 附：起不来的四种样子（全是我撞过的原文）

服务起不来时，屏幕上只有这几行，而且是**立刻返回提示符**（没有 `Application startup complete.`）：

| 你打成这样 | 屏幕上出现 | 真正的原因 |
|---|---|---|
| 在仓库根 `uv run uvicorn stage1/day004_fastapi_basics/code/python/01_first_app:app --port 8711` | `ERROR:    Error loading ASGI app. Could not import module "stage1/day004_fastapi_basics/code/python/01_first_app".` | 冒号左边要的是**模块名**，不是**文件路径**。斜杠它看不懂 |

| `uv run uvicorn 01_first_appp:app --port 8711` | `ERROR:    Error loading ASGI app. Could not import module "01_first_appp".` | 文件名打错了 |
| 端口已被别的程序占着 | 见第八节，它甚至**先印一句 startup complete 再报错** | 反直觉，专门说 |

顺带一句实话：在仓库根写 `uv run uvicorn stage1.day004_fastapi_basics.code.python.01_first_app:app --port 8711`
（把斜杠全换成点）**是能的**，我试过，它照样 200。Python 3 允许这样找包。
但那一长串没人想打，而且它要求你站在仓库根——今天统一**先 `cd` 到 `code/python` 再起**，别折腾。

## 二、路径参数：URL 里那一段是什么类型，你说了算

### ① 建文件（终端 A 的那个目录）

```bash
cd stage1/day004_fastapi_basics
cat > code/python/02_path_param.py <<'PY'
from fastapi import FastAPI

app = FastAPI()

items = [
    {"id": 1, "name": "pen", "price": 3},
    {"id": 2, "name": "cap", "price": 5},
    {"id": 3, "name": "box", "price": 10},
]


@app.get("/")
def read_root():
    return {"service": "day004", "count": len(items)}


@app.get("/items/{item_id}")
def read_item(item_id: int):
    return {"you_asked_for": item_id, "type": type(item_id).__name__}
PY
```

比第一节多三样：

1. **一个模块顶层的 list**。`items` 定义在两个函数**外面**，所以两个函数都读得到它。
   ——它就是今天的数据库。第八节会告诉你这个选择的代价。
2. `len(items)`：数一个 list 里有几项，就是 JS 的 `items.length`。**今天只新给这一个函数**，后面没有别的。
3. 函数参数上的 `: int`。昨天以前你写类型注解只是写给人看的，**今天它开始干活了**。


看到 `Application startup complete.` 就算好了。之后每节我只贴**访问日志**，不再贴启动那四行。

### ④ 再打六条边界（这一小组是给你看清 `int` 的边界的）

真跑：

```

{"you_asked_for":-3,"type":"int"} [200]
{"you_asked_for":7,"type":"int"} [200]
{"detail":[{"type":"int_parsing","loc":["path","item_id"],"msg":"Input should be a valid integer, unable to parse string as an integer","input":"1x"}]} [422]
{"detail":[{"type":"int_parsing","loc":["path","item_id"],"msg":"Input should be a valid integer, unable to parse string as an integer","input":" "}]} [422]
{"you_asked_for":3,"type":"int"} [200]
```

终端 A 接着印六行，一一对上：

```
INFO:     127.0.0.1:53970 - "GET /items/2.5 HTTP/1.1" 422 Unprocessable Content
INFO:     127.0.0.1:53971 - "GET /items/-3 HTTP/1.1" 200 OK
INFO:     127.0.0.1:53972 - "GET /items/007 HTTP/1.1" 200 OK
INFO:     127.0.0.1:53973 - "GET /items/1x HTTP/1.1" 422 Unprocessable Content
INFO:     127.0.0.1:53974 - "GET /items/%20 HTTP/1.1" 422 Unprocessable Content
INFO:     127.0.0.1:53975 - "GET /items/%2B3 HTTP/1.1" 200 OK
```

### ⑤ 对上

**第 2 条：`"type":"int"`。**
URL 里所有的东西天生都是**字符串**——HTTP 报文里 `"2"` 就是字符 `2`。
但函数体里 `item_id` 的类型是 `int`。是 `: int` 这个注解让 FastAPI 在调用你的函数**之前**做了转换。
如果你写 `item_id: str`，这里就会印 `"type":"str"`，`abc` 也不再报 422。

**第 3 条：422 那句报错里，`loc` 是关键。**

```json
{"type":"int_parsing", "loc":["path","item_id"], "msg":"...", "input":"abc"}
```

- `loc` 第一项 `path`：错在**路径参数**上。（第三节你会看到 `"loc":["query","min_price"]`。）
- `loc` 第二项 `item_id`：错在**哪个参数**上，写的是你函数签名里那个名字。
- `input`：**你原本传进来的原始字符串**。转换失败时它原样保留。

看 `loc` 就能一眼定位该改哪一行，这就是第四节、第六节全部按 `loc` 读报错的原因。

**第 4 条 `[404]`，和上面 `/nope` 那次不是一回事。**
这次 `/items` 是**你迟早要注册**的路径，只是这一节的文件里还没有它。
第三节把它加进来，同一个 URL 就变 200 了。**记住这一对：404 = 没有这条路由。**

**`: int` 的判断标准是「这段字符串能不能变成一个 int」，不是「像不像正整数」。**
`-3` 能，`+3` 能，`007` 能（前导零在转换时掉了，所以回的是 `7`）；`2.5` 不能（`int("2.5")` 在 Python 里本来就直接报错）；
`1x` 不能——**它不做「能读多少算多少」，要么整段是整数，要么 422。**

**`%20` 那条最值得看一眼**：你 URL 里打的是 `%20`，回显里 `input` 是一个**空格** `" "`。
说明 **URL 解码发生在类型转换之前**——FastAPI 拿到手的已经是解好码的字符串，它没去解第二遍。
于是你只传一个空格进去，`int(" ")` 失败。这条以后调试前端会碰到。

**对照你的 JS**（不跑，只是把名字对上）：

```js
app.get("/items/:item_id", (req, res) => {
  // Express 只给你 req.params.item_id，而且永远是字符串
  // 想要数字得自己写 Number(req.params.item_id)，转失败了 Express 不管
});
```

| | Express | FastAPI |
|---|---|---|
| 拿路径参数 | `req.params.item_id`（字符串） | 函数参数 `item_id`（按注解转换） |
| 转换失败 | 它不管，你自己 `NaN` | 直接 422，`loc` 告诉你是哪个 |

## 三、查询参数：有没有默认值，决定它必不必填

### ① 建文件

### ⑤ 对上

**一条规则，今天用得完：函数参数有默认值 = 这个查询参数选填；没有默认值 = 必填。**
就是 Python 函数本身的规则（Day 2 讲过 `def f(a, b=1)`），FastAPI 只是**读你的函数签名**，
没有发明第二套规矩。

逐条看：

- **第 1 条 `count:3`**：没传 `min_price`，走默认值 `0`，三条都 `>= 0`，全进来。
- **第 2 条 `count:2`**：`min_price=5`，`pen`（3）被筛掉。注意回显里 `cap` 的 `price` 正好等于 5 也留下了——我写的是 `>=`。
- **第 3 条 422**：和第二节一模一样的 `int_parsing`，只是 `loc` 变成了 `["query", "min_price"]`。
  **`loc` 里那个词（`path` / `query` / `body`）就是 FastAPI 在告诉你它从哪儿读到的这个值。**
- **第 4 条 `q=x` → 和第一条一模一样，`count:3`，200。**
  **这是这一节真正的收获。** `q` 是一个**你的函数里根本没有的参数**。
  FastAPI 没有报 422，没有报 404，它**把这个看不懂的查询参数直接扔了**，然后照常跑。
  意味着你拼错查询参数的名字（`minprice`、`min_Price`）时，**不会有任何报错**，
  只会得到一个「好像什么过滤都没发生」的结果。这是最难查的一类 bug。
- **第 5 条 `count:0, items:[]`**：`min_price=99` 一条都不满足，返回**空 list**。
  状态码还是 200。「查了，没有」和「没这个路由」（404）是两件事。
- **第 6 条 `min_price=`（空值）→ 422，`input: ""`**。
  空字符串也照样要过 `int()`，而 `int("")` 是失败的。
  注意它和第 4 条的区别：`?q=x` 是**没见过这个键**，直接忽略；
  `?min_price=` 是**见过这个键但值不行**，报错。
- **④ 那条 `missing` / `input: null`**：必填参数没给。
  以后你自己写前端时，看到 422 且 `msg` 是 `Field required`，**第一反应是「有个参数我忘传了」，
  不是「后端坏了」**。

**对照 JS**：

```js
app.get("/items", (req, res) => {
  req.query.min_price          // 字符串 "5"，没传就是 undefined
  // Express 里 min_price 的默认值要自己写：const mp = Number(req.query.min_price) || 0
});
```

| | Express | FastAPI |
|---|---|---|
| 拿查询参数 | `req.query.xxx`（永远是字符串或 `undefined`） | 函数参数名，按注解转换 |
| 默认值 | 自己写 `|| 0` | 写在参数上 `min_price: int = 0` |
| 没传又没默认值 | `undefined`，你自己处理 | 422 `Field required` |
| 传了没用的键 | 留在 `req.query` 里给你看 | **静默忽略**（第 4 条） |

## 四、路由是按注册顺序匹配的，文档不算数

现在回答今日问题。

### ① 建文件

```bash
from fastapi import FastAPI

app = FastAPI()


@app.get("/dup")
def dup_first():
```

还有一件我替你看过的：上面那四条 curl 你都在终端 A 里能看到对应日志行，
但**启动输出里没有任何一行 `warning`**——`/dup` 重复注册这件事，框架一句都没提。

### ⑤ 对上

**`/dup` → 「先注册的那个」，而且起服务时零警告。**
两条一模一样注册的东西，第二条**永远跑不到**，也不会有人告诉你。
`dup_second()` 是一段死代码，它在文件里、在 `import` 时无条件执行了装饰器、在文档里可能出现，但没有任何请求会走到它。
**这是今天最安静的一类 bug**：不报错、不崩溃、不警告，只是结果永远是旧的。

**`/bad/me` → 422，不是 200。**
FastAPI 匹配路由**只看注册顺序，从上往下，第一个能对上的就赢**。
`/bad/{bid}` 里的 `{bid}` 能吞掉**任何**一段路径——`7`、`me`、`abc` 都算对上。
所以 `/bad/me` 一进来就被 `bad_by_id(bid="me")` 接走，然后卡在 `int` 转换上，报 422。
「`/bad/me` 更精确、应该优先」——**它不做这件事**。

**把这两条换一下顺序，结果就变了。** 你现在可以自己推出来（这一条我没替你跑，是作业第 2 题）：
`/bad/me` 排到上面之后，`GET /bad/me` 回 200 的 `{"handler":"bad_me"}`，
而 `GET /bad/7` 不受影响（`/bad/me` 对不上 `7`，还是会往下找到 `{bid}`）。
**这就是为什么真实项目里，静态路径要写在参数路径前面。**

**`loc` 再一次给出答案**：`["path", "bid"]`。
它告诉你「我以为你要给 `bid` 一个整数」，于是你回头去看注册顺序，而不是去查 `me` 为什么不是数字。

**方法不冲突，路径才冲突。**
`@app.get("/things")` 和 `@app.post("/things")` 是**两条独立的路由**，各回各的，都在。
所以「重复注册」的判断要连着方法一起看：`get + get` 同路径 = 后者死；`get + post` 同路径 = 完全正常。

**`PUT` / `DELETE` → 405 `Method Not Allowed`，不是 404。**
这是两个不同的诊断信号，务必分清：

| 状态码 | 含义 | 你该去查什么 |
|---|---|---|
| **404 Not Found** | 这个**路径**我一条路由都没匹配上 | 路径拼错了 / 忘了注册 |
| **405 Method Not Allowed** | 路径匹配上了，但**方法**没有 | 前端用了 `PUT`，你只写了 `GET` |
| **422 Unprocessable Content** | 路由 matched、类型不过 | 看 `loc`，改传参那一侧 |

第七节我会给出第四种最阴的：**该 404 却回 200**。

**`openapi.json` 里有它 ≠ 它能被命中。**
文档是「你注册过什么」的清单，不是「什么请求能走到哪」的清单。
这两件事在第四节之前从来没分开过，今天它们分开了。
你在 `/docs` 页面上会看到 `/bad/me` 明明白白列着，还能点开点 Try it out——
点了之后拿到的就是那个 422。

**对照 JS**：Express 完全一样——它也是按 `app.get(...)` 的书写顺序从上往下匹配，先中的赢。
你在 Express 里踩过的这个坑，在这里一个不落地会再踩一遍。区别只是 Express 连 `openapi.json` 都没有，
你连「它注册过」都查不到。

## 五、端点写 `def` 还是 `async def`：今天全用 `def`，而且有证据

昨天你学了整整一天的 `async def` / `await`。今天所有端点我都写**普通 `def`**。
这一节给你两条硬证据，说明这不是偷懒。

### ① 建文件

```bash
cd stage1/day004_fastapi_basics
cat > code/python/05_def_or_async.py <<'PY'
import time

from fastapi import FastAPI

app = FastAPI()


@app.get("/quick")
def quick():
    return {"msg": "我马上回来"}


@app.get("/sleepy")
def sleepy():
    time.sleep(2)
    return {"msg": "我睡了 2 秒"}


@app.get("/boom")
def boom():
    return 1 / 0


@app.get("/async-quick")
async def async_quick():
    return {"msg": "我是 async def，里面一个字都没等"}


@app.get("/async-sleepy")

    time.sleep(2)
    return {"msg": "我是 async def，里面写了 time.sleep"}
```

### ⑤ 对上

**A 组 0.001 秒：普通 `def` 端点里 `time.sleep` 不卡别人。**
D 组那三行 `run_in_threadpool` / `anyio.to_thread.run_sync` / `context.run(func, *args)` 就是原因——
**FastAPI 看见你的端点是普通 `def`，就把它丢给一个工作线程去跑**，事件循环本身空着，别人照样进得来。
这就是昨天第七节 `asyncio.to_thread` 那条出路，只不过这次是**框架替你调了**。
你那行 `time.sleep` 一个字都没改，它阻塞的是**别人的线程**。

**B 组 1.698 秒：同一行 `time.sleep`，搬进 `async def` 就卡住了。**
`async def` 的端点 FastAPI **不丢线程**，它直接在事件循环那个唯一的线程上跑。
于是昨天的判据原样生效：**`await` 是「我等，你们先走」；`time.sleep` 是「我不走，你们都别想走」。**
这里没有 `await`，只有 `time.sleep`，所以事件循环被按住整整 2 秒。
（`1.698` 不是 `2.0`：`/async-sleepy` 比你早发 0.3 秒，`/async-quick` 只等了剩下的那一段。）

**C 组 1.696 秒——这一条最贵。**
`/quick` 是**普通 `def`**，它自己在工作线程里跑得飞快。但它的**结果要送回事件循环才能发出去**。
事件循环被 `/async-sleepy` 按住了，回不去。
**所以：一个 `async def` 端点里写了一行 `time.sleep`，会把整个服务卡住，连普通 `def` 端点一起陪葬。**
昨天这是「一个脚本慢了一点」，今天是「全站 2 秒无响应」。

**A 组那两行日志的顺序**：`/quick` 印在 `/sleepy` 前面，但端口号 `54904 < 54905` 说明 `sleepy` 才是先来的。
**访问日志是「谁先完成谁先印」，不是「谁先来」**——昨天第四节 `gather` 那条结论，在服务端日志上又出现一次。

**D 组：客户端收到的是 `Internal Server Error` 这 21 个字母，不是 JSON。**
你的端点抛异常时，FastAPI **不包装**、不转 JSON，直接给一段纯文本 + 500。
（第六节你会看到另一种：同样是「你收到了字符串」，但那次的字符串在**响应头**里写着 `application/json`。）
状态码 500 的意思是「**你这边炸了**」，跟第三、四节的 422（「你传的东西不对」）是两类问题：

| | 谁的错 | 正文 |
|---|---|---|
| 422 | 调用方传的参数不对 | JSON，带 `loc` |
| 405 | 调用方用错方法 | JSON `{"detail": ...}` |
| 500 | **你的代码抛异常** | 纯文本 `Internal Server Error`，详情只在终端 A 的栈里 |

**看栈的读法，今天就得学会**：从下往上，**第一个不含 `.venv` 的 `File` 行就是你的问题所在**。
这次它指向 `05_def_or_async.py, line 21, in boom`，一眼就到。
前面那 30 帧全在 `.venv/lib/python3.13/site-packages/` 底下，那是框架内部，跟你无关。

**那今天到底该写哪个？** 一句话：

> **端点里有 `await` 就写 `async def`；端点里全是同步的（普通函数、`time.sleep`、老库）就写普通 `def`。**
> 写错方向不会报编译错，只会让服务在某些请求下整体卡住。

今天全部端点都是普通 `def`，因为它们里面一个 `await` 都没有。
Day 6 教中间件和异常处理时，你会看到 `async def` 端点什么时候是**必须**的。

**对照 JS**：Node 只有一个线程，且**没有**「普通函数自动丢线程池」这回事。
所以 Express 里写 `sleep(2000)` 同步阻塞，效果等于这里 B/C 两组的合体——**全站卡住**。
Python 这边多出「普通 `def` 自动进线程池」这一条活路，是它相对 Node 的一个真实差别。

## 六、第一个 POST：`Content-Type` 决定你收到 dict 还是字符串

### ① 建文件

```bash
cd stage1/day004_fastapi_basics
cat > code/python/06_post_body.py <<'PY'
from fastapi import FastAPI

app = FastAPI()

items = [
    {"id": 1, "name": "pen", "price": 3},
    {"id": 2, "name": "cap", "price": 5},
    {"id": 3, "name": "box", "price": 10},
]


@app.get("/items")
def list_items(min_price: int = 0):
    found = []
    for it in items:
        if it["price"] >= min_price:
            found.append(it)
    return {"count": len(found), "items": found}


@app.post("/items")
def create_item(payload: dict):
    items.append(payload)
    return {"count": len(items)}
PY
```

这一节把 `/` 和 `/items/{item_id}` 都删掉了，只留两条——这样 POST 的每一次后果都能在 `GET /items` 里看到。

`payload: dict` 是这一节的全部内容：**参数类型写成 `dict`，FastAPI 就把请求体当 JSON 读进来交给你**。
注意它和第三节那个 `min_price: int` 走的是**完全不同的两个通道**：
一个从 URL 的 `?` 后面读，一个从 HTTP 报文正文里读。`loc` 里那个词（`query` / `body`）就是在区分这两个通道。

### ⑤ 对上

**四条 422，四种病，全靠 `type` + `loc` 区分：**

| 你干了什么 | `type` | `loc` | 读法 |
|---|---|---|---|
| 没写 `-H 'content-type: application/json'` | `dict_type` | `["body"]` | 「我收到了东西，但它不是 dict」 |
| `-H` 写了但 `-d` 忘了一半 | `missing` | `["body"]` | 「正文这个字段整个没给」 |
| 给了，但不是合法 JSON | `json_invalid` | `["body", 1]` | 「第 1 个字符就解不开」 |
| 是合法 JSON，但是个数组 | `dict_type` | `["body"]` | 回到第一行 |

**第一条最值得看：`input` 是 `"{\"name\":\"pen\"}"`——一个字符串。**
你 POST 的字面内容和成功那次一模一样，但因为它没声明自己是 JSON，
curl 默认发的是 `application/x-www-form-urlencoded`，FastAPI 没把它当 JSON 解，
于是**一整段 `{"name":"pen"}` 变成一个孤零零的字符串**递到你手上。
`dict_type` 的 `input` 里那些反斜杠就是 JSON 在转义引号——**那是字符串的证据**。

**curl 为什么「默认」就错了？** 因为 `-d` 这个参数的默认行为就是表单编码。
浏览器 `fetch` 也一样：`fetch(url, {method:"POST", body: JSON.stringify(x)})` 不带 `headers`，
发出去的东西**没有 content-type**，FastAPI 一样给你 `dict_type`。
这是前端接 Python 后端时最高频的一个 422。

**`json_invalid` 的 `loc` 是 `["body", 1]`，多了一个数字。**
那个 `1` 是**出错位置**（第 1 个字符）。`ctx.error` 直接说人话：
`Expecting property name enclosed in double quotes`——JSON 的键必须带双引号，你写了 `{name:pen}`。
JS 对象字面量允许裸键名，JSON 不允许。这是两个东西，别混。

**`{"name":"cup","price":7}` 这条被老老实实收下了，而且它没有 `id`。**
`payload: dict` 只保证「是一个 dict」，**不保证里面有什么**。
`items.append(payload)` 也就照单全收。最后一行 `min_price=3` 的结果里能看到它——
它没有 `id`，但 `price` 是 7，所以过得了筛选；而 `ink`（`price: 2`）被筛掉了。
**这一节你只需要看到「它收下了」，第七节会让你看到「收下的代价」。**

**对照 JS**：

```js
// Express：必须自己挂中间件，否则 req.body 是 undefined
app.use(express.json());
app.post("/items", (req, res) => { req.body /* dict */ });
```

| | Express | FastAPI |
|---|---|---|
| 读 JSON 正文 | 要 `app.use(express.json())` | 写 `payload: dict` 就行 |
| content-type 不对 | 中间件不认，`req.body` 是 `undefined` | 422，`loc: ["body"]` |
| 校验结构 | 一律不管 | 今天也一律不管（Day 5 才管） |

`payload: dict` 只要求「是个 dict」，`{"name":"no-price"}` 是个 dict，两个键都没有也照收。
**从这一刻起，这个服务的数据里多了一条脏东西，而它一句都没反对。**

**接下来才是重点：同一批命令，有的还是 200，有的变成 500 了。**

| 命令 | POST 前 | POST 后 | 为什么 |
|---|---|---|---|
| `GET /items/2` | 200 | **还是 200** | `pen` 排在第 1 个、`cap` 第 2 个，命中后 `return`，循环**根本没走到第 4 项** |
| `GET /items/3` | 200 | **还是 200** | 同理，第 3 个位置命中，脏数据在第 4 个位置，没碰到 |
| `GET /items/4` | 200（那个说谎的 200） | **500** | 没有 id=4，循环要走完全部 4 项 → 读到脏数据 → `it["id"]` 不存在 |
| `GET /items/99` | 200（同样说谎） | **500** | 同理，它也要走完整个 list |
| `GET /items` | 200 | **500** | 筛选要对每一项算 `it["price"]` |
| `GET /items?min_price=99` | 200 空列表 | **500** | **哪怕一条都筛不进来，`if it["price"]` 也要对每一项求值一次** |

**看懂这一组对比，你今天最大的收获就有了：**
一个只读接口，在没人碰它的时候是好的；
有人 POST 了一条不合结构的 JSON，**它没报错**；
从此这个接口的行为**取决于你要查的那条数据排在第几位**。
`/items/3` 活着、`/items/4` 死了——**同一份数据、同一个函数、同一个时刻**。

这种 bug 到了线上就是「有的用户打不开，有的能打开」，
而日志里的栈指向的是**读**的那一行，不是**写**进去的那一行。**写进去的可能是三天前的一个请求。**

**`min_price=99` 那条尤其值得停一下。**
你会本能地以为「`min_price=99` 什么都匹配不上，肯定最安全」。
不是。筛选的写法是 `for` + `if`，**`if` 里的表达式对每一项都要算一次**，
算到脏数据那一行就炸。少筛 ≠ 少走。

**两个 `KeyError` 都在读数据的那一行，不在写数据的那一行。**
就算把第 26 行那个「故意做错的 200」修成 404，`/items/99` 照样要走完整个 list 才拿到 404，
照样炸。**所以那个洞修不完——真正要修的是 POST。**
这就是明天：让 POST 在门口就把不合结构的东西拦住，而不是让它走进来。

**关于那个 `{"error": "..."}`：为什么它是个坏设计，今天你能说出三条理由**

1. 状态码 200 表示「成功」，前端 `if (res.ok)` 会判成成功，然后把 `error` 当数据用。
   对比第一节的 `/nope` → **404 才是「没有」的正确说法**。
2. 它把「没找到」变成了函数的**正常返回值**，于是返回类型不再统一：
   找到时返回一个 item（`{"id":..,"name":..,"price":..}`），没找到时返回 `{"error":..,"item_id":..}`。
   **下游没法写。** Day 5 的响应模型就是把这件事钉死。
3. 它不出现在任何日志里。终端 A 打的是 `"GET /items/99 HTTP/1.1" 200 OK`——
   **一个绿色的 OK**。你以后查「为什么这个 id 是空的」，翻服务端日志翻不到。

**对照 JS**：Express 里你写 `res.json({error:"..."})` 同样是 200，一模一样的坑。
正确的写法一直是 `res.status(404).json(...)`。Python 这边对应的东西 Day 6 给。

## 九、今天的产出：`app.py`，以及该看到的现象

大纲这一天的产出是「搭建第一个 GET/POST 接口」。

### ① 建文件（逐字抄，不要自己发挥）

```bash
cd stage1/day004_fastapi_basics
cat > code/python/app.py <<'PY'
from fastapi import FastAPI

app = FastAPI()

items = [
    {"id": 1, "name": "pen", "price": 3},
    {"id": 2, "name": "cap", "price": 5},
    {"id": 3, "name": "box", "price": 10},
]


@app.get("/")
def read_root():
    return {"service": "day004", "count": len(items)}


@app.get("/items/{item_id}")
def read_item(item_id: int):
    for it in items:
        if it["id"] == item_id:
            return it
    return {"error": "没有这个 id", "item_id": item_id}


@app.get("/items")
def list_items(min_price: int = 0):
    found = []
    for it in items:
        if it["price"] >= min_price:
            found.append(it)
    return {"count": len(found), "items": found}


@app.post("/items")
def create_item(payload: dict):
    items.append(payload)
    return {"count": len(items)}
PY
```

**注意注册顺序**：`/items/{item_id}` 写在 `/items` **前面**。
第四节你学过「先注册的先赢」，这里为什么可以不守那条？
因为 `/items` 只有**一段**，`/items/{item_id}` 是**两段**，`{item_id}` 吞不到一段的路径——
它们**不可能互相截胡**。会被截胡的是段数相同的情形（`/bad/me` 和 `/bad/{bid}`）。
