## 第 1 题 · `pick` 是冤枉的

### 判据

```python
tally[word] = ...        # 原地改那个只建了一次的默认字典   → 有 bug
return chosen + [items[0]]  # 造一个新列表，默认的那个没被碰   → 没 bug
```

**今天的真判据不是"有没有写 `=[]`"，是"那个默认对象有没有被原地改"。**

`pick` 的 `pick.__defaults__ : ([],)` 就是证据——
两次调用之后，那个默认列表**还是空的**。它被读了，没被改。

（`chosen + [x]` 是**列表相加**，Python 里这个运算返回新列表，两边都不动。
`chosen.append(x)` 才是原地改。这一字之差就是今天全部内容。）

### 修好之后的真实输出

`count` 用 `None` 哨兵，`Session` 把 `visits` 搬进 `__init__`：

```
=== 修好的第 1 段 ===
{'a': 1}
{'b': 1}
r1 is r2 : False

=== 修好的第 2 段 ===
{'home': 1} {}
s1.visits is s2.visits : False
```

**看第 1 段现在印 `{'a': 1}` 和 `{'b': 1}`，不再是 `{'a': 1, 'b': 1}` 两遍。**
这才是"每次调用都是新字典"的样子。

### 一句容易被绕进去的话

`check.py` 第 1 项会把 `pick` **判红**，因为它只用 AST 查写法。
**检查器查写法，不查行为。** 这不是 `check.py` 的 bug，是所有 lint 的固有边界——
你现在知道了，以后看到 lint 报"可变默认参数"，你知道它在防的是**可能性**，不是**已经发生的错**。

## 第 2 题 · `shout`

### 参考实现

```python
import functools


def shout(fn):
    @functools.wraps(fn)
    def loud(*args, **kw):
        print("!!!")
        result = fn(*args, **kw)
        print("!!!")
        return result

    return loud


@shout
def hello(name):
    print(f"hello {name}")
    return name


hello("ada")
print("hello.__name__ :", hello.__name__)
print("repr(hello)    :", repr(hello))
```

真跑：

```
!!!
hello ada
!!!
hello.__name__ : hello
repr(hello)    : <function hello at 0x1054bc900>
```

**三处必须注意**：

1. `result = fn(...)` 然后 `return result`。
   如果你写成 `print("!!!")` 后面不 return，`hello("ada")` 的返回值就是 `None`——
   **装饰器把返回值吞了**，这是写装饰器最常见的一种错，`wraps` 救不了它。
2. `repr` 里**没有** `<locals>` 了：`<function hello at 0x...>`。
   因为 `wraps` 把名字和内层归属都改回了原函数。**看不到 `loud` 就是对的。**
3. 内层函数叫什么**完全不影响**加没加 `wraps` 的结果。我这里叫 `loud`，你叫别的也一样。

### 删掉 `@functools.wraps(fn)` 那一行

```
!!!
hello ada
!!!
hello.__name__ : loud
repr(hello)    : <function shout.<locals>.loud at 0x108778900>
```

`repr` 里 `<locals>` 那一段现在有意义了，读作「`shout` 里面那个 `loud`」。

我把 `loud` 换成 `burp`（加着 wraps）验过一次，`repr` 变成 `<function hi at 0x...>`——
**内层叫什么已经被彻底藏起来了**。这就是 `wraps` 干的事。

## 第 3 题 · `Cart`

```python
from dataclasses import dataclass, field


@dataclass
class Cart:
    items: list = field(default_factory=list)
    totals: dict = field(default_factory=dict)

    def add(self, name, price):
        self.items.append(name)
        self.totals[name] = price
        return self.items
```

真跑（`c1` 加三样，`c2` 什么都不加）：

```
['pen', 'cap', 'box']
{'pen': 3, 'cap': 5, 'box': 10}
[] {}
c1.items is c2.items : False
连续新建两个，字段也一样吗 : [] {}
```

**`field(default_factory=dict)` 不是笔误多写了一个**：两个字段都是可变的，
所以**两个都要**。只给 `items` 给、`totals` 不给，你会看到：

```
ValueError: mutable default <class 'dict'> for field totals is not allowed: use default_factory
```

（我把 `totals` 单独改坏跑过。原话就是这句，箭头照样指在 `@dataclass` 那一行。）

### 最后一行为什么重要

`Cart().items, Cart().totals` 印 `[] {}` ——
**连续造两个，互不影响。** 这一行是整题的收口：
它证明 `default_factory` 和第四节的 `__init__` 干的是同一件事——
**把"每次建一个新的"搬到每次都会执行的地方去。**

## 第 4 题 · `calculator.py` 参考实现

放在 `stage1/day002_python_core/code/python/calculator.py`。

```python
"""calculator.py —— Day 2 主产物"""

import functools
from dataclasses import dataclass, field


def running_total(nums, acc=None):
    if acc is None:
        acc = []
    for n in nums:
        acc.append((acc[-1] if acc else 0) + n)
    return acc


def log_call(fn):
    @functools.wraps(fn)
    def inner(*args, **kw):
        print(f"-> {fn.__name__}")
        return fn(*args, **kw)

    return inner


class Calculator:
    def __init__(self):
        self.value = 0
        self.history = []

    @log_call
    def add(self, n):
        self.value += n
        self.history.append(self.value)
        return self.value

    @log_call
    def sub(self, n):
        self.value -= n
        self.history.append(self.value)
        return self.value


@dataclass
class Receipt:
    items: list = field(default_factory=list)


if __name__ == "__main__":
    c1 = Calculator()
    c2 = Calculator()
    print(c1.add(5), c1.sub(2))
    print("c1.history :", c1.history)
    print("c2.history :", c2.history)
    print(running_total([1, 2, 3]))
    print(running_total([9]))
    r1, r2 = Receipt(), Receipt()
    r1.items.append("a")
    print(r1.items, r2.items)
```

### 直接跑 `calculator.py` 的真实输出

```
-> add
-> sub
5 3
c1.history : [5, 3]
c2.history : []
[1, 3, 6]
[9]
['a'] []
```

### 跑 `check.py` 的真实输出

```
-> add
-> add
-> sub
✓ 1. 写法 · 没有可变默认参数（零个可变默认值；running_total 的默认值是 ['None']）
✓ 2. 写法 · 没有可变类属性（类体里没有 = [] 这种写法）
✓ 3. 行为 · 两个计算器互不污染（c1.history=[5] 而 c2.history=[]）
✓ 4. 行为 · 端到端算式与契约一致（add/sub 与 history、running_total 两次调用都独立）
✓ 5. 行为 · 装饰器没吃掉函数名（装饰器 ['log_call'] 存在，且 __name__ 保住了）
✓ 6. 行为 · dataclass 用 default_factory（隔离正常：['Receipt.items']）

Day 2 过关：6/6 项自动检查通过，3 项需你自批
```

退出码 `0`。

**开头那三行 `-> add / -> add / -> sub` 是正常的**，教案第七节讲过：
那是 `check.py` 的第 3、4 项为了验你，自己真去调了 `c1.add(5)`、`c.add(5)`、`c.sub(2)`。
`if __name__ == "__main__":` 里那八行一句都没印，说明开关起作用了。

### `running_total` 那一行怎么想的

```python
acc.append((acc[-1] if acc else 0) + n)
```

`acc[-1] if acc else 0` 读作「`acc` 里有东西就取最后一个，空就取 0」。
累计和的定义就是"上一个累计值 + 当前这个"，而"上一个累计值"在第一次时不存在，用 0 代替。

**上面那个 `for n in nums:` 和 `acc[-1]`，就是教案第九节补的那块地基**（第 5 段跑的 `[1, 3, 6]` 就是本题的结果）。

**注意它写的是 `acc.append(...)`——原地改 `acc`。**
所以 `acc=None` 那个哨兵**必须是这题第一个被想清楚的地方**；
你要是写成 `acc=[]`，`running_total([9])` 就会拿到 `[1, 3, 6, 15]`（第二次调用接着上次的和加）。

### 三个最可能被写错的地方

**1. `add` 一定要 `return self.value`。**
不 return 的函数返回 `None`，`print(c1.add(5), c1.sub(2))` 会印 `None None`，
第 4 项报 `实际 (None, None)`。

**2. `history` 追加的是操作后的当前值，不是传进来的 `n`。**
追加 `n` 的话 `add(5)` `sub(2)` 的 history 会是 `[5, 2]`，第 4 项报
`history 应是 [5, 3]（每次操作后的当前值），实际 [5, 2]`。
**注意它只红第 4 项**，不像类体共享那样一次红三项。

**3. `@dataclass` 里可变字段要用 `field(default_factory=...)`。**
写成 `= []` 的话 `check.py` **一行 `✓` 都不印**就退出：

```
✗ calculator.py 导入阶段就炸了：ValueError: mutable default <class 'list'> for field items is not allowed: use default_factory
```

**"一句都没印"不是脚本坏了，是你的文件在顶层就崩了。**
这正是第七节：`check.py` 拿起你文件的那一刻，执行到 `@dataclass` 那行就抛了。

## 今天可带走的四句

1. **`def`、`class`、文件顶层，都是"执行一次"的语句**，不是声明。
2. **默认值只在 `def` 那一秒求值一次**；JS 每次调用重新求值——所以这个 bug 你从没见过。
   **"我一直这么写的"是待验证的假设，不是理由。**
3. **写装饰器必带 `@functools.wraps(fn)`**，判据只看 `repr()` 里还有没有 `<locals>`。
4. **文件级的演示代码裹进 `if __name__ == "__main__":`**，
   它管的是"我自己的打印"，不管"别人正常调用我的函数"。

四句合成一句：

> 碰到一个对象行为奇怪，先问**它是哪一刻被建出来的**，再问**有没有人在原地上改它**。
