# Day 2 · 为什么 Python 的默认参数和 JS 不一样

> 计划里这一天是「Python 核心语法速通：数据类型、函数、类与对象、装饰器」。
> 你有十年编程经验，语法速通对你是浪费——所以本日只挑**会让你写错的那部分**：
> Python 和 JS 在「什么时候求值」上的三处真实分歧。

---

## 今日问题

同一段逻辑，两种语言，结果不同：

```javascript
// JS
function f(x = []) { x.push(1); return x; }
console.log(f(), f(), f());     // [ 1 ] [ 1 ] [ 1 ]
```

```python
# Python
def f(x=[]):
    x.append(1); return x
print(f(), f(), f())            # [1, 1, 1] [1, 1, 1] [1, 1, 1]
```

两边都是「三次调用，每次往默认值里 push 一个 1」。JS 每次得到新数组，
Python 三次得到**同一个列表**，而且里面已经有 3 个元素。

**为什么？以及：这个差异还会以哪两种面貌出现，把你坑第二次、第三次？**

---

## 学习目的

搞清一条规则：**Python 的函数默认值在「定义时」求值一次，JS 在「每次调用时」求值。**

这条规则会以下面三种面貌出现，今天全部见到：

1. 可变默认参数（上面这个）
2. 装饰器在 `def` 那一刻就执行，不是在你调用时
3. 类体里写的 `tags = []` 是**所有实例共享**的——对应 JS 的 `static`，不是实例字段

学完你要能写出一个「多个实例互不污染、带调用日志」的计算器类，
并且能解释为什么第一版是错的。

---

## 学习内容

### 一、默认参数：定义时求值一次

`def f(x=[])` 这行代码执行时，`[]` 就被创建出来了，**存在函数对象上**。
之后每次调用不传 `x`，拿到的都是那同一个列表。

上面那个 `[1,1,1] [1,1,1] [1,1,1]` 还藏了第二层：`print` 的三个参数是**先全部求值再打印**的，
所以三次调用都跑完了（列表里已经有 3 个 1），然后同一个列表被打印了三遍。
如果你想看到累积过程，得分三次 print：

```python
print(f())   # [1]
print(f())   # [1, 1]
print(f())   # [1, 1, 1]
```

正确写法是用 `None` 当哨兵：

```python
def f(x=None):
    if x is None:
        x = []
    x.append(1)
    return x
```

### 二、装饰器：`@` 那一行就执行了

实测顺序（本机跑出来的）：

```python
order = []
def deco(f):
    order.append("装饰时")
    def w(*a, **k):
        order.append("调用时"); return f(*a, **k)
    return w

@deco
def hello(): return "hi"
order.append("定义完成后")
hello()
print(order)   # ['装饰时', '定义完成后', '调用时']
```

`装饰时` 排在 `定义完成后` **前面**——因为 `@deco` 等价于 `hello = deco(hello)`，
它是定义语句的一部分，在模块加载时就跑了。

JS 的装饰器（TC39 stage 3）语义相同：装饰器在类/函数定义时求值。这点两边一致。

**不一致的是名字**：

```python
print(hello.__name__)   # w      ← 你的名字被吃掉了
```

修复靠 `functools.wraps`：

```python
import functools
def deco(f):
    @functools.wraps(f)      # 加了这行
    def w(*a, **k): return f(*a, **k)
    return w
```

实测：加上之后 `hello.__name__` 回到 `hello`。

这件事在你后面写 FastAPI 时会变成真 bug：FastAPI 靠函数签名和 `__name__`
生成 OpenAPI 文档，装饰器不吃掉名字，你的接口文档里就会出现一堆 `w`。

### 三、类属性 vs 实例属性：这是与 JS 分歧最大的一处

```python
class C:
    tags = []                 # 类属性
    def __init__(self, n): self.name = n

c1, c2 = C("a"), C("b")
c1.tags.append("x")
print(c1.tags, c2.tags)       # ['x'] ['x']   ← 共享！
```

同样的写法在 JS 里语义**完全相反**：

```javascript
class C { tags = []; constructor(n){ this.name = n; } }
const c1 = new C("a"), c2 = new C("b");
c1.tags.push("x");
console.log(c1.tags, c2.tags);   // [ 'x' ] []   ← 隔离
```

对照关系是这样的：

| 你想要的效果 | Python 写法 | JS 写法 |
|---|---|---|
| 每个实例独立 | `self.tags = []`（写在 `__init__` 里） | `tags = []`（类字段） |
| 所有实例共享 | `tags = []`（写在类体里） | `static tags = []` |

**Python 类体里直接写的东西 = JS 的 `static`**。这一句记牢，能省你两天的调试。

### 四、dataclass 会替你拦住这个坑

```python
from dataclasses import dataclass, field

@dataclass
class E:
    tags: list = []
```

直接报错，文案是：

```
ValueError: mutable default <class 'list'> for field tags is not allowed
```

正确写法：

```python
@dataclass
class D:
    name: str
    tags: list = field(default_factory=list)

d1, d2 = D("a"), D("b")
d1.tags.append("x")
print(d1, d2)   # D(name='a', tags=['x']) D(name='b', tags=[])   ← 隔离
```

`dataclass` 比手写类严格：它**在定义时就拒绝**可变默认值。
Day 5 你会遇到 Pydantic，它在这件事上更严格（连类型不符都拒绝）。
Python 生态的趋势是：把「运行时才发现的错」提前到「定义时就报错」。
