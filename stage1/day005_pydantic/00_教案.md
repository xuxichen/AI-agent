## 今日问题

下面这个模型，第三节会让你亲手建（现在只需要看懂它长什么样）：

```python
class Thing(BaseModel):
    name: str
    price: int
    score: float
    flag: bool
```

五条请求，只差一个值（`score` 和 `flag` 每条都给对了，为了不误伤）：

```
$ curl -s -w ' [%{http_code}]' -X POST -H 'content-type: application/json' \
    -d '{"name":"ab","price":"7","score":2,"flag":true}' http://127.0.0.1:8742/t
{"name":"ab","price":7,"score":2.0,"flag":true} [200]

$ ... -d '{"name":5,"price":7,"score":2,"flag":true}' ...
{"detail":[{"type":"string_type","loc":["body","name"],...}]} [422]

$ ... -d '{"name":"ab","price":7.0,"score":2,"flag":true}' ...
{"name":"ab","price":7,"score":2.0,"flag":true} [200]

$ ... -d '{"name":"ab","price":7.5,"score":2,"flag":true}' ...
{"detail":[{"type":"int_from_float","loc":["body","price"],...}]} [422]

$ ... -d '{"name":"ab","price":true,"score":2,"flag":true}' ...
{"name":"ab","price":1,"score":2.0,"flag":true} [200]
```

这个库的名字叫「数据**校验**」。可这五条里，第 1 条把 `"7"` 改成了 `7`，第 3 条把 `7.0` 改成了 `7`，
第 5 条把 `true` 改成了 `1`，第 1 条还把 `2` 改成了 `2.0`——**四条都在放行之前偷偷改了你送回的值**。
而第 2 条，`5` 变成 `"5"` 对任何人来说都不难，它偏偏 422。

**问题：它到底是在校验类型，还是在转换类型？如果说是校验，为什么 `7.0` 过而 `7.5` 不过；
如果说是转换，为什么 `int` 变不成 `str`？这条线画在哪里？**

第三节回答。答案不是「Pydantic 比较宽松」，是一条**有方向**的规则，
而且它和昨天第二节那条「URL 里的 `"7"` 会被转成 `7`」是同一件事。

### ④ 为什么第 3 条没崩、第 2 条崩了

这是昨天第十节留的账，今天再走一遍，因为**今天全部八节都是在堵这一个洞**：

- `?min_price=1` 那条（`list_items`）要遍历**整个 list**，每一条都读 `it["price"]`。
  第 4 条脏数据在里面，走到它就 `KeyError` → 500。
- `/items/1` 那条（`read_item`）只要遍历到第 1 项就 `return` 了，**根本走不到第 4 项** → 200。
- `/items/99` 也遍历到底，但它读的是 `it["id"]`，而脏数据**有 `id`**（我传了 `"id":9`）→ 200。

**换一种脏法，结论就反过来**：如果你 POST 的是 `{"name":"ghost"}`（有 `price` 缺 `id`），
那 `/items/1` 就会变成 500，`?min_price=1` 反而会 200。

**这就是 `payload: dict` 的真正问题**：它不是「少一个键会报错」，
它是**让错误离开案发现场**——往 list 里塞东西的那次请求返回 200，
崩的是下一个人的、跟你毫无关系的请求。你在终端里看见 500，
往上翻日志要找的那个「是谁塞进来的」，**它当时是 200**。

### ⑤ 对上

**先对上 ③ 那五条。**

- **第 1 条 422，`type` 是 `missing`，`msg` 是 `Field required`。**
  和昨天 ④ 那条「必填查询参数没给」是**同一个 `type`、同一句 `msg`**。
  区别在 `input`：昨天是 `null`（根本没有那个参数），今天是 `{"name":"cap"}`——
  **`missing` 的 `input` 放的是「它拿到的那一整坨东西」**。少了一个字段，它把整个 body 印给你看。
- **第 2 条 `int_parsing`**：昨天第二节（路径参数）、第三节（查询参数）都是这一句，
  今天 `loc` 的第二个词从 `path` / `query` 变成了 **`body`**。
  昨天那条规则继续成立：**`loc` 的第一个词就是 FastAPI 从哪儿读到的这个值。**
- **第 3 条：你传的 `"id":99` 不见了**，回来的 `id` 是 `4`。
  `ItemIn` 里没写 `id`，所以 `99` 在门口就被扔了，
  后面 `data["id"] = len(items) + 1` 自己补的才是真的。
  **这是「多余键」和昨天的关键差别**：昨天的 `dict` 会原样收下你的 `id`，
  今天它进不来（第四节把这条讲全）。
- **第 5 条 `/items` 里的形状**：看第 4、5 两项——`{"name":...,"price":...,"id":...}`，
  **`id` 在最后**。前三项是 `{"id","name","price"}`。
  因为 dict 保持你插入的先后顺序（Day 3 第十一节那条），
  而 `model_dump()` 按**模型里声明的顺序**给出 `name`、`price`，我们的 `data["id"] = ...` 是最后加上去的。
  顺序不影响取值，但**它证明了一件事**：这个 dict 是模型生成的，不是你传进来的那个。

**再对上 ④ 那八行。**这一组是今天第二节真正的收获：

1. **`Plain 的注解： {'x': <class 'int'>}`** —— 光写 `x: int` 不赋值，Python **只是把这句话记在
   `__annotations__` 这个本子上了**，什么都没创建。所以下一行 `Plain.x` 会 `AttributeError`
   （Day 2 第四节：类属性必须 `x = 5` 这种**带赋值**的写法才真的存在，`WithValue.x` 印出了 5）。
2. **`ItemIn 的字段表：{'name': FieldInfo(annotation=str, required=True), ...}`** ——
   `BaseModel` 干的事就是：**把你的注解翻译成一张字段表，并且在 `__init__` 里按这张表检查你传进来的东西**。
   `required=True` 是 `name: str` 后面**没有 `= 号`** 换来的。
3. **`ItemIn.__init__ is BaseModel.__init__ = True`** ——
   你没写 `__init__`，`ItemIn` 用的就是 `BaseModel` 那个，一个字节都没换。
   这就是「为什么这个 class 里一句 `def` 都没有，却能 `ItemIn(name="pen", price=3)`」的全部答案。
   （Day 2 第六节 `@dataclass` 那一节你已经见过同一种把戏：`Good.__init__.__name__` 印出 `__init__`，
   那个 `__init__` 也是别人帮你生成的。**`BaseModel` 就是一个会校验的 `@dataclass`**。）
4. **`it = name='pen' price=3`** —— 这是它自己的 `print` 格式，不是 dict（dict 是 `{'name': 'pen', ...}`，
   带花括号、键带引号）。**它是 `ItemIn`，不是 `dict`**：`type(it).__name__` 印的是 `ItemIn`。
5. **最后一行崩了：`TypeError: 'ItemIn' object is not subscriptable`。**
   `it.name` 通得上，`it["name"]` 通不上。
   **昨天你在 `list_items` 里写的 `it["price"]` 是方括号取值的写法。**
   这条先记住，第五节整节讲它——那是今天最容易写错的一个字。

**对照 JS**：

```js
// JS 里没有「类型注解」这个东西能被运行时读到
const ItemIn = { name: "pen", price: 3 };   // 就是一个对象，取值只能 .name 或 ["name"]
// 校验要自己写：if (typeof body.name !== "string") return res.status(422)...
// class-validator / zod 这类库要的是同一件事，但都得你自己调一次 parse
```

| | JS（Express + 手写） | Python + Pydantic |
|---|---|---|
| 声明字段 | 没有这个概念 | `name: str`（注解） |
| 运行时读注解 | 读不到（编译后没了） | **读得到**（`__annotations__`） |
| 谁执行校验 | 你写的 `if` | `BaseModel.__init__`，你不写 |
| 校验失败 | 你自己 `res.status(422)` | FastAPI 替你抛，回 422 |

### ⑤ 对上：规则只有三条，但有方向

**方向一：被引号包起来的东西，允许被重新解释成别的类型。**

| 你给的 | 字段要 | 结果 |
|---|---|---|
| `"7"` | `int` | `7` |
| `" 7 "` | `int` | `7`（**顺手把两头空格去了**） |
| `"2.5"` | `float` | `2.5` |
| `"abc"` | `float` | 422 `float_parsing` |
| `"true"` / `"yes"` / `"1"` | `bool` | `true` |

这一条不是「宽松」，是**为了容错**。JSON 传数字最常见的事故就是前端把 `7` 拼成了 `"7"`
（表单里的值、query string 拼出来的东西，全都是字符串）。
**昨天第二节你见过同一件事**：URL 里 `/items/7` 的 `7` 本来就是字符串，
`item_id: int` 把它变成了 `7`。今天只是把同一套规则搬到了 body 上。

**方向二：数字之间只允许「无损」地走。**

| 你给的 | 字段要 | 结果 |
|---|---|---|
| `7.0` | `int` | `7` —— 小数部分没有东西，丢不掉，放行 |
| `7.5` | `int` | 422 `int_from_float`，`msg` 原话：`got a number with a fractional part` |
| `2` | `float` | `2.0` —— 第 1 条里就发生了，`score:2` 回来是 `score":2.0` |
| `true` | `int` | `1` |
| `false` | `int` | `0` |
| `2` | `bool` | 422 `bool_parsing` —— `2` 不能不撒谎地变成 true/false |

`7.0` 和 `7.5` 这一对是今日问题里最难猜的一对。**它们都是 JSON 的数字，
区别只在「变成 int 会不会丢东西」**。会丢就 422，不丢就 silently 改了给你。

**方向三：任何不是字符串的东西，永远变不成字符串。**

| 你给的 | 字段要 | 结果 |
|---|---|---|
| `5` | `str` | 422 `string_type` |
| `true` | `str` | 422 `string_type` |
| `null` | `str` | 422 `string_type`（**`null` 也不行**，第八节讲它怎么才算行） |

三个方向合起来回答今日问题：**它两头都干，但有一张固定的通行方向表**——
`str` 是这张表的最下游，任何东西都能流向它，**它不流向任何东西**。

**第 7 条 `d '{}'`：四个字段四条 `missing`，一次全报。**
这是昨天没有的行为。昨天一个请求只有一个参数要转，报错只有一条；
今天 `detail` 这个 list 里装了四条，顺序就是**你在 class 里声明字段的顺序**。
**模型是一次把整个 body 读完、所有字段一起判的**，不是读一个错一个就返回。
这个「一次全报」是第一节那个洞的另一半：`dict` 只会在你用到那个键的时候才崩，
而模型在门口就把所有毛病一次说完。

**对照 JS**：

```js
JSON.stringify(7)      // "7"    —— 数字变字符串，JS 到处放行
String(7)              // "7"
7 + ""                 // "7"
"7" * 1                // 7      —— 字符串变数字，JS 也放行
// JS 是两个方向都自动，所以前端永远分不清 "7" 和 7
```

| | JS | Pydantic |
|---|---|---|
| `"7"` → `int` | 允许 | 允许 |
| `7` → `str` | 允许（而且到处发生） | **拒绝**（`string_type`） |
| `7.5` → `int` | 允许（`7.5 \| 0`，你要么自己写） | **拒绝** |
| 谁改的值 | 运算时临时改，原件不动 | **改了就定了**，你 return 的就是转过的 |

最后一行是真正的分别：JS 的转换是**每次用每次都转一遍**，
Pydantic 是**进门转一次，之后那个值就是它了**。所以 `data["id"] = ...`（第二节那种）
拿到的 `price` 已经是 `7`，不是 `"7"`。

### ④ 把 Day 2 那笔账翻出来：`= []` 这次为什么不共享

```bash
    tags: list[str] = []

    acc.append("x")
```

### ⑤ 对上

**先对上 ③ 那十四条。**

- **第 1 条：`stored` 里有 `score` 和 `tags`。** 你**一个都没传**，它们却带着默认值出现在结果里。
  `model_dump()` 会把默认值一起导出——**「没传」和「传了默认值」在落库之后完全一样**。
  第八节的 `age: int | None` 就是专门用来区分这两种情况的。
- **第 2、3 条：`string_too_short` / `string_too_long`，`msg` 里带**`at least 2 characters`。
  注意这两条**新出现了一个键：`ctx`**。昨天的 422 只有四个键（`type`/`loc`/`msg`/`input`），
  今天带约束的错会多一个 `ctx`，里面是**你自己在 `Field` 里写的那个数**
  （`{"min_length": 2}`、`{"le": 150}`）。**`ctx` 是给机器看的，`msg` 是给人看的，同一份数据两遍。**
- **第 4 条 `age:200` → `type` 是 `less_than_equal`**，不是 `too_big`。
  这是 Pydantic 用 Python 运算符的名字给错分类：`ge`→`greater_than_equal`、`le`→`less_than_equal`。
  **看 `type` 猜规则，比看 `msg` 更准**（`msg` 是英文句子，会改；`type` 是枚举名，稳定）。
- **第 7 条 `score:101` → `ctx` 是 `{"le": 100.0}`（带 `.0`）**，
  而我写的是 `le=100`。因为 `score` 声明成 `float`，约束被一起升成了 float。
- **第 10 条：`loc` 变成了 `["body","tags",0]`。**
  **`loc` 里第一次出现整数**——那是**下标**。第 0 个元素不是字符串。
  这一条比第三节那条更重要：报错信息能精确指到**数组里第几个**。
- **第 11 条 `isAdmin` 消失了**，`stored` 里根本没有它。
  昨天 `?q=x` 是「查询参数里看不懂的键，扔掉，但函数还能看到全部 dict」；
  今天多余的键**连 `payload` 上都长不出来**——`payload.isAdmin` 会 `AttributeError`。
  想让它报错而不是被扔，得写 `model_config = ConfigDict(extra="forbid")`，那是今天的洞之一（第十节）。
- **第 13 条 `age:"20"` → 200，`age` 是 `20`**：方向一的规则在 `Field` 约束**之前**执行。
  `"20"` 先变成 `20`，再拿 `20` 去比 `ge=0, le=150`。
  所以**约束查的是转完之后的值**，你不能用 `Field` 表达「我要求它必须是字符串形式的数字」。
- **第 14 条：`name` 和 `age` 两条错一起报**，顺序还是声明顺序。

**再对上 ④——这一段是今天最该记住的一处。**

Day 2 第二节，你背过一条铁律：**`def f(acc=[])` 的默认值只在 `def` 那一行求值一次，
所以三个调用共享同一个 list**。今天模型字段上写的 `tags: list[str] = []` 长得一模一样，
而 ④ 的结果是：

```
m1.tags = ['x']
m2.tags = []
m1.tags is m2.tags = False
f() 第三次 = ['x', 'x', 'x']
```

**同样是 `= []`，模型字段上不共享，函数参数上共享。**
`is` 那一行 `False` 就是证据：`m1.tags` 和 `m2.tags` 是两个不同的 list。
而 `f()` 三次越滚越长，是 Day 2 那个原封不动的坑。

为什么不共享：`BaseModel.__init__` 在没收到这个字段时**不是直接把 `[]` 交出去，
而是复制一份新的**（还记得第二节 ④ 那句 `ItemIn.__init__ is BaseModel.__init__ = True` 吗——
那个 `__init__` 里做的事比你想的多）。

**这里有个陷阱值得你注意**：Day 2 你还学过 `@dataclass` 对同一件事的处理是**直接拒绝**——
`@dataclass` 里写 `tags: list = []` 会在类定义那一行就抛
`ValueError: mutable default <class 'list'> for field tags is not allowed`，
逼你写 `field(default_factory=list)`（Day 2 第六节的原文，箭头指在 `@dataclass` 上那一行）。
三个库、同一种危险、**三种答案**：

| 写法所在 | `= []` 的后果 |
|---|---|
| 函数参数（Python 本体） | 静默共享，越滚越长 |
| `@dataclass` 字段 | **当场抛**，逼你写 `field(default_factory=list)` |
| `BaseModel` 字段 | 静默复制，安全，**但什么都不告诉你** |

**这条规则不是 Python 的规矩，是库的规矩。**
以后你看到一个危险的写法，先别问「Python 允不允许」，要问「**我用的这个库碰到它会干什么**」。

**`description="用户名"` 这一整轮 curl 里一个字都没出现**。它到文档里去了：

```bash

```

真跑（`openapi.json` 整份是**一行**、几十 KB，所以这里只把 `UserIn` 那一段抽出来印全。
管道里那个 `python3` 只 `import json` 做格式化，**它不参与任何校验**，换成 `uv run python` 结果一样）：

```
{
  "properties": {
    "name": {
      "type": "string",
      "maxLength": 20,
      "minLength": 2,
      "title": "Name",
      "description": "用户名"
    },
    "age": {
      "type": "integer",
      "maximum": 150.0,
      "minimum": 0.0,
      "title": "Age"
    },
    "score": {
      "type": "number",
      "maximum": 100.0,
      "minimum": 0.0,
      "title": "Score",
      "default": 0.0
    },
    "tags": {
      "items": {
        "type": "string"
      },
      "type": "array",
      "title": "Tags",
      "default": []
    }
  },
  "type": "object",
  "required": [
    "name",
    "age"
  ],
  "title": "UserIn"
}
```

**`Field` 里的约束会被翻译成 OpenAPI 的字段**（`min_length`→`minLength`，`ge`→`minimum`），
`required` 那个 list 里只有 `name` 和 `age`——**`score` 和 `tags` 有默认值，所以不在里面**。
`tags` 那一项里的 `"items": {"type": "string"}` 就是 `list[str]` 在文档里的形状：
**「这是个 array，元素是 string」这两句话分开写**。前端拿这份 JSON 就能生成一个表单，
`maximum: 100.0` 会变成输入框上的限制——**你今天在 Python 里写的每一个 `Field` 参数都在这儿被用第二次**。
`description` 只出现在文档和 `/docs` 页面上，**运行时一点作用都没有**：
它不会让报错变得更好看，也不会挡下任何请求。它是写给**下一个读你接口的人**的。

**对照 JS**：

```js
const schema = z.object({
  name: z.string().min(2).max(20),
  age: z.number().int().min(0).max(150),
});
const parsed = schema.safeParse(body);   // ← JS 里这一步要你自己写、自己判、自己回 422
```

| | zod（JS 生态） | Pydantic |
|---|---|---|
| 长度约束 | `.min(2)` 链式 | `Field(min_length=2)` 关键字 |
| 谁来调校验 | 你写 `safeParse` | FastAPI 在进函数前替你调 |
| 校验失败怎么办 | 你处理 `parsed.error` | 直接 422，你看不到 |
| 文档 | 要另一个库生成 | `/docs` 自动就有 |

**最后一列就是大纲把 Pydantic 和 FastAPI 放一起讲的原因**：
你写的约束不只是给运行时用来挡请求的，同一份声明还直接变成了前端能看到的接口文档。

## 五、模型不是 dict：点取得到，方括号取会把服务弄崩

第二节 ④ 那行 `print(it["name"])` 崩在你自己眼前。这一节把它接到 HTTP 上——
**同一个 `ItemIn`，你把它塞进 list 里存着，昨天那句 `it["price"]` 会变成什么。**

### ① 建文件

```bash
cd stage1/day005_pydantic
cat > code/python/06_not_dict.py <<'PY'
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class ItemIn(BaseModel):
    name: str
    price: int


wrong = []
right = []


@app.post("/wrong")
def add_wrong(payload: ItemIn):
    wrong.append(payload)
    return {"n": len(wrong)}


@app.get("/wrong")
def read_wrong():
    total = 0
    for it in wrong:
        total = total + it["price"]
    return {"total": total}


@app.get("/wrong-attr")
def read_wrong_attr():
    total = 0
    for it in wrong:
        total = total + it.price
    return {"total": total}


@app.get("/wrong-keys")
def read_wrong_keys():
    return {"first": wrong[0], "type": type(wrong[0]).__name__}


@app.post("/right")
def add_right(payload: ItemIn):
    right.append(payload.model_dump())
    return {"n": len(right)}


@app.get("/right")
def read_right():
    total = 0
    for it in right:
        total = total + it["price"]
    return {"total": total}


@app.post("/raw")
def raw(payload: ItemIn):
    return payload
PY
```

**整节的机关全在两个 list 上**：`wrong` 装的是**模型对象本身**（`wrong.append(payload)`），
`right` 装的是 `payload.model_dump()` —— 一个 dict。
而读它们的那两行代码**一模一样**：`total = total + it["price"]`。

`type(wrong[0]).__name__` 是 Day 1 那招「别猜它是什么类，问它」。这里拿它当证据用。


### ⑤ 对上

**第 3 条 500，原因就在栈的最后那句：`TypeError: 'ItemIn' object is not subscriptable`。**
`subscript` 就是「方括号取下标」这件事的名字。方括号取的是**容器里的键**，
而 `ItemIn` 是对象，不是容器。第二节 ④ 那行 `print(it["name"])` 崩的是**同一句话**，
只不过当时崩在你终端，今天崩在请求处理里，所以你只看到一个 `Internal Server Error`。

**第 4 条 `[200] {"total":8}`**：`8 = 3 + 5`。
一个字母的差别——`it["price"]` 换成 `it.price`——同一批数据立刻读得通。
**对象不是不能读，是换个读法。**

**第 5 条是整节最需要你记住的一条：`{"first":{"name":"pen","price":3},"type":"ItemIn"}`。**
花括号里那个 `first` 看上去就是一个再普通不过的 JSON 对象，
可 `"type"` 那一栏写着 `ItemIn`——它是个模型对象。
**FastAPI 认识模型对象，`return` 出去之前它替我们转成 JSON。**
所以：**在服务响应里你永远看不出「手里这个不是 dict」，崩只崩在你自己的 Python 代码里。**
昨天那种 `d["键"]` 写法会一路跟着你进到今天，而今天进门的东西不再是 dict 了。

**第 6 条 `[200]`**：`return payload`，一行加工都没有，回来的还是 JSON。这条是第 5 条的对照组。

**第 7、8 条**：`/right` 存进去的是 `payload.model_dump()`，一个 dict；
读取端那句一模一样的方括号代码又通了，`{"total":3}`。

所以今天真正要往脑子里装的就一条：

| 你手上拿的是 | 读字段 | 写字段 / 长期保存 |
|---|---|---|
| `dict`（昨天） | `d["price"]` | `d["id"] = 4` |
| 模型对象（今天） | `payload.price` | `data = payload.model_dump()`，然后对 `data` 用左边那一栏 |

**`model_dump()` 是这两个世界之间唯一的桥。**
它的名字可以记：`dump` 是「倒出来」，倒出来的形状是 dump 的那个词——**dict**。
（它还有一个反向的 `Model(**data)`，今天不碰，因为你用 `payload` 的时候从来不需要自己 new。）

**对照 JS**：

```js
// JS 里没有这个墙：对象就是对象，d["price"] 和 d.price 是同一件事的两种写法
const d = { price: 3 };
d["price"];  // 3
d.price;     // 3
```

Python 里 `[]` 和 `.` 是**两套完全不同的机制**（前者查容器，后者取属性），
所以「昨天能用的写法今天不能用」在 JS 里根本不成其为问题，在 Python 里今天要专门防。

## 六、嵌套模型：模型里放模型、放 `list[模型]`，以及 `| None` 那三个字母

大纲这条叫「嵌套模型」。它其实只有一件新东西：**字段的类型可以是你自己刚写的那个类**。

### ① 建文件

```bash
cd stage1/day005_pydantic
cat > code/python/07_nested.py <<'PY'
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()


class Address(BaseModel):
    city: str
    zipcode: str = "000000"


class Order(BaseModel):
    order_id: int
    addr: Address
    lines: list[Address] = []
    note: str | None = None


class ItemIn(BaseModel):
    name: str = Field(min_length=2, description="商品名")
    price: int = Field(ge=0, description="单价")


class Bad(BaseModel):
    note: str = None


class Good(BaseModel):
    note: str | None = None


@app.post("/order")
def order(payload: Order):
    return {"got": payload.model_dump()}


@app.post("/batch")
def batch(payload: list[ItemIn]):
    total = 0
    for it in payload:
        total = total + it.price
    return {"n": len(payload), "total": total}


@app.post("/bad")
def bad(payload: Bad):
    return {"got": payload.model_dump()}


@app.post("/good")
def good(payload: Good):
    return {"got": payload.model_dump()}
PY
```

`Order` 那四行里有三样新东西，先各给一句话（本节 ⑤、⑥ 会各自展开）：

| 写法 | 读法 |
|---|---|
| `addr: Address` | 这个字段的值是**另一个模型**——你写的第一个「自定义类型出现在注解里」 |
| `lines: list[Address] = []` | 一个 list，**里面每个元素**都得是 `Address`；不给就默认空 list |
| `note: str \| None = None` | 要么是一个 `str`，要么是 `null`，不写就是 `None` |

### ⑤ 少写 `| None` 会怎样（两条路径，六条 curl）

`Bad` 和 `Good` 只差 `| None` 三个字符。各打三条：不给这个字段、显式给 `null`、给一个 `5`。

```
{"got":{"note":null}} [200]
{"got":{"note":null}} [200]
{"detail":[{"type":"string_type","loc":["body","note"],"msg":"Input should be a valid string","input":5}]} [422]
```

**`Bad` 的第 1 条和第 2 条是今天最阴的一处**：什么都不给，它 200，回来的还是 `"note":null`；
明确给一个 `null`，它 422。同一个 `None`，两种命运。

### ⑥ 对上

**先对上 `loc`——它从「两个词」长成了「一条路径」。**

| 条 | `loc` | 读法 |
|---|---|---|
| ③ 第 2 条 | `["body","addr"]` | body 里的 `addr` |
| ③ 第 5 条 | `["body","lines",0,"city"]` | body → `lines` → **第 0 个元素** → 它的 `city` |
| ④ 第 3 条 | `["body",1,"price"]` | body → **第 1 个元素** → 它的 `price` |
| ④ 第 4 条 | `["body"]` | 只有两个词：错的是 **body 本身**，它不是 list |

第一到第三节那条规则（`loc` 的第一个词就是 FastAPI 从哪儿读到的）**继续成立**，
今天只是往后追加：字符串是**键名**，裸数字是**下标**。
`["body","lines"]` 和 `["body","lines",0,"city"]` 差一个下标，
说的是「整个 list 没给对」和「第 0 个元素里少一个键」——**排查时这一字之差就是省半小时**。

**再对上 `input`。**
③ 第 5 条的 `input` 是 `{"zipcode":"1"}`——**只有那一个元素**，不是整个 body。
④ 第 3 条的 `input` 是 `{"name":"cd"}`——同理。
和第四节那条规矩合起来读：**`missing` 的 `input` 永远是「出错的那一层」当时拿到的东西**。
错在顶层，印整个 body；错在第 0 个元素里，印那个元素。

**第 1 条里那个 `"zipcode":"000000"` 你没传**，它补上了——**嵌套层里的默认值和顶层一样生效**。
`Address` 的 `zipcode: str = "000000"` 和第四节 `score: float = Field(0.0)` 是同一种东西。

**第 4 条 `model_attributes_type` vs `list_type`**：
`addr` 该是个对象却给了字符串 → `model_attributes_type`，`msg` 是
`Input should be a valid dictionary or object to extract fields from`（**「给我一个 dict 或者对象，我好按字段表来读」**）；
`lines` 该是个 list 却给了对象 → `list_type`。
**类型错的是「这个字段该是什么」，`type` 就照着那个名字报。**

**③ 第 6 条和 ④ 第 2 条**：`"lines":[]` 和 `"n":0`。空 list 是**合法值**，不是缺字段——
`lines` 有默认值 `[]`，不给就用它，`n = len(payload) = 0`，`total = 0`（循环一次没走）。

**⑤ 那个阴的怎么解释**：Pydantic **不校验默认值**，它只在「你真的传了这个字段」时才按类型检查。
所以 `note: str = None` 里那个 `None` 从来没进过类型这道门，它就是个漏网的值；
而你显式写 `{"note":null}` 时它进门了，`str` 不收 `null`，于是 422。
**结论只有一条：可空的字段必须写 `X | None`，别指望 `= None` 那半边替你说话。**
`Good` 的第 6 条也在告诉你：`| None` 放开的是 `null`，**不是「随便什么都行」**，`5` 照样 422。

**对照 JS（TypeScript）**：

```ts
interface Order {
  order_id: number;
  addr: Address;          // ← 和今天一模一样的一件事
  lines: Address[];
  note?: string | null;   // ← 今天写成 str | None = None
}
```

写法几乎逐字对上，所以你会觉得眼熟。**唯一的、也是本节全部的差别**：
这段 TS 编译完就没了，`{"addr": "sh"}` 一样能进你的函数；
而今天这五行 `class Order(BaseModel)` 在**运行时真的在查**，`"sh"` 被挡在门外，还给了你一个能定位到下标的 `loc`。

**收尾：`Ctrl+C` 关掉 8745 的服务。**

## 七、`response_model`：它替你挡掉字段，也替你补上默认值，还能把你弄崩

前六节管的全是**进门**：body 对不对、类型转不转、嵌套怎么查。
这一节管**出门**。出门这件事以前你从没管过——`return` 什么就发什么。

### ① 建文件

```bash
cd stage1/day005_pydantic
cat > code/python/08_response.py <<'PY'
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class UserIn(BaseModel):
    name: str
    password: str
    age: int = 0


class UserOut(BaseModel):
    name: str
    age: int


class PublicUser(BaseModel):
    username: str
    age: int = 0


USERS = [
    {"username": "a1", "password": "pw1", "age": 20},
```

一个文件里三个模型，职责各不相同，这是今天唯一一处「名字要起清楚」的地方：

两处格式和前面六节不一样，先说清楚：

- **`loc` 的第一个词变成了 `response`**，而且这里是**圆括号**（Python 的 tuple），不是 JSON 的方括号——
  因为它从来没打算发给客户端，它只印在你终端 A 的日志里。
- **`line 39` / `line 54` 不是崩的那一行，是那条路由的装饰器行**；

### ⑤ 对上

**第 1 条 vs 第 2 条：一字不差的函数体，两种响应。**
`{"name":"abc","password":"123","age":0}` 是 `model_dump()` 原样出去；
加了 `response_model=UserOut` 之后，`password` **被删掉了**，`age` **被补成了 0**。
所以 `response_model` 干的是两件事，**同时**干：

| 它对「你 return 的东西」做的事 | 在哪一条看到 |
|---|---|
| **过滤**：模型里没有的键，删 | 第 2 条 `password` 没了、第 5 条 `password` 没了 |
| **补默认值**：模型里有、你没给的，按默认值填 | 第 2 条 `age: 0`、第 5 条第二项 `age: 0` |

**第 5 条 vs 第 6 条是最该记住的一对。**
同一个 `return USERS`：带 `response_model` 的那条只给 `username` + `age`，
不带的那条**把 `password` 全发出去了**，而且它 200、它合法、它一句错都不报。
**「不把敏感字段 return 出去」这件事，以前靠你自觉，今天开始可以靠一个声明。**
（注意它不是加密，也不是脱敏，是**白名单**：只有 `PublicUser` 里写了的键能出去。）

**第 3 条 422、第 4 条 500、第 7 条 500：这三条一起把今天的规矩收口。**

| 谁出错 | `loc` 第一个词 | 状态码 | 谁的错 |
|---|---|---|---|
| 调用方 body 给错了 | `body` | **422** | **他的错**，他会收到那段 JSON 并自己改 |
| 你 return 的东西不合法 | `response` | **500** | **你的错**，他只能看到一个 `Internal Server Error` |

同一种 `missing`、同一句 `Field required`，一个报给客户端，一个只写进你的日志。
**以后你看到 422 先怀疑请求，看到 500 先查自己 return 的那句话**——`loc` 的第一个词就是判决书。

**第 7 条还有一层**：`loc` 是 `('response', 0, 'username')`。
第六节那个「下标」在响应侧照样有：**out 模型里某个元素缺必填字段，报的是它的位置**。

**出门的声明也进文档**：


`/leak` 的 200 响应是**一个空 dict `{}`**，意思是「我不知道它长什么样」；
`/safe` 的是一个 `$ref`，指向 `UserOut` 的定义。
前端拿 `/docs` 看这两条接口，一条能自动补全字段，一条只能靠猜——
**这就是「要不要写 `response_model`」在协作上的实际代价**，不是风格问题。

**对照 JS**：

## 八、大纲那道产出题：一个用户注册接口

到这儿，「请求体校验、响应模型、嵌套模型」三样都在手上了。这一节把它们拼成大纲点名的那个东西。

### ① 建文件

```bash
cd stage1/day005_pydantic
cat > code/python/09_signup.py <<'PY'
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()


class UserIn(BaseModel):
    username: str = Field(min_length=3)
    password: str = Field(min_length=6)
    age: int | None = None


users = []


@app.get("/")
def root():
    return {"service": "day005"}


@app.post("/signup")
def signup(payload: UserIn):
    for u in users:
        if u["username"] == payload.username:
            return {"error": "用户名已存在", "username": payload.username}
    rec = payload.model_dump()
    users.append(rec)
    return {"ok": True, "stored": rec}


@app.get("/users")
def list_users():
    return {"count": len(users), "users": users}
PY
```

长度、必填、可空、类型，全在注解里说完了。
函数体里剩下的那个 `for` 循环才是**真正的业务规则**——「同名要挡」这件事 Pydantic 帮不了你，
它只知道字段长什么样，不知道你服务器里已经存过什么。

### ⑤ 对上

**第 1 条里那个 `"age":null` 你没传**。
第四节说过「有默认值的字段不出现在 `required` 里」，第八节的 `model_dump()` 又补了下半句：
**「不给」和「给 `null`」在 dump 出来以后长得一模一样**。
文档说「可以不给」，dump 说「我一定会给」——**这两句不矛盾，它们说的不是同一个时刻**。
（顺带一提，这也是为什么 `age` 在文档里是 `anyOf [integer, null]`：`| None` 那三个字母照样翻译进了文档，
而 `required` 里没有它，因为 `= None` 给了它默认值。）

**第 2 条 `[200] {"error":"用户名已存在"}`：这一条是明天要补的洞，今天它还在。**
状态码没变，正文换了一个中文键。客户端**只能靠读 `"error"` 这个键名来判断成败**——
它得写 `if (data.error)`，而不能写 `if (!res.ok)`。
「注册成功回 200、用户名重复也回 200」这两件事在真实项目里都会被写进 API 文档，
而文档一骗人，前端就只能靠试。**开头说的第 3 处偏离就是这个：今天不动 `status_code`，Day 6 用 `HTTPException` 一起补。**

**第 3、4 条**：同一个 `type`（`string_too_short`）在两个字段上，`ctx` 各自写着 `min_length` 是几。
**约束报错的多少完全取决于 `Field` 里写的那个数**——这就是第四节把 `Field` 单独列一节的理由。

**第 5 条 vs 第 6 条**：`"abc"` 422、`null` 200。
`anyOf` 的意思是「**这几条里有一条通就行**」：`"abc"` 既不是 `integer` 也不是 `null`，两条都不通。
所以 `X | None` 放开的是 `null` 这一个值，**不是「这个字段随便给」**（第六节 ⑤ 最后一句在这儿再验一遍）。

**第 8 条 `/users`：三个 `password` 全在上面。**
没有 `response_model`，它就是第七节那条 `/users-raw`。
**你今天已经会补它了**——`01_作业.md` 第 1 题就让你补这一处。

**对照 JS**：

```js
// express-validator：约束写得像链，而且要点一次人来执行
app.post("/signup", [
  body("username").isLength({ min: 3 }),
  body("password").isLength({ min: 6 }),
], (req, res) => {
  const errors = validationResult(req);
  if (!errors.isEmpty()) return res.status(422).json(errors);   // ← 这一步 Pydantic 没有，因为是 FastAPI 替你做的
  ...
});
```

| | Express 那套 | 今天 |
|---|---|---|
| 约束写在哪 | 路由参数的中间件数组里 | **模型类里**（和端点分家） |
| 谁执行 | 你 `if (!errors.isEmpty())` | 框架在进函数前 |
| 响应侧 | 没有对应物 | `response_model=` |
| 文档 | 另一个库（swagger-jsdoc 等） | 同一份模型自动出 |

```bash
class ItemIn(BaseModel):
    name: str = Field(min_length=2)
    price: int = Field(ge=0)


class ItemOut(BaseModel):
    id: int
    name: str
    price: int


items = [
    {"id": 1, "name": "pen", "price": 3},
    {"id": 2, "name": "cap", "price": 5},

@app.get("/")

    return {"service": "day005", "count": len(items)}


@app.get("/items/{item_id}", response_model=ItemOut)
def read_item(item_id: int):
    for it in items:
        if it["id"] == item_id:
            return it
    return {"error": "没有这个 id", "item_id": item_id}


@app.get("/items", response_model=list[ItemOut])
def list_items(min_price: int = 0):
    found = []
    for it in items:
        if it["price"] >= min_price:
            found.append(it)
    return found


@app.post("/items", response_model=ItemOut)
def create_item(payload: ItemIn):
    data = payload.model_dump()
    data["id"] = len(items) + 1
    items.append(data)
    return data
```

### ⑤ 第 5 条那个 500：昨天它是 200，今天它升级了

昨天第七节你第一次撞脏数据时，`GET /items/99` 回的是 `200` + `{"error":...}`。
今天同一条命令，函数体一行没改，它变成 500 了。终端 A 里（**中间那几十帧 `.venv` 内部的我省了**）：

**看懂这三条 `missing` 只需一句话**：
`response_model=ItemOut` 要求出去的东西得有 `id`、`name`、`price` 三个键，
而你 `return` 的是 `{"error": ..., "item_id": ...}`，**三个键一个都没有**，于是三个 `missing`。
`input` 那一栏印的就是你 return 的那坨东西（第二节说的「`missing` 的 `input` 是它拿到的那一整坨」，响应侧照样成立）。

**注意 `line 30` 那一句底下没有源码行**（第七节第一条栈也是这样）。
前面几节的 `TypeError` 会把你指到具体那一行代码；这一类不是——
**它指的是那条路由的装饰器行，因为崩不在你的代码里，在 FastAPI 拿你的返回值去套模型的那一步。**
找这种错时别看行号，看 `input` 里那坨你 return 的东西。

**这个 500 是今天的终点，也是明天的起点**：它比昨天的 200 好，因为终端 A 有栈；
它也坏得多，因为**客户端收到的仍然只是一句 `Internal Server Error`，什么信息都没有**。
「找不到就该回 404」这件事，Pydantic 帮不了你，那是 Day 6 的 `HTTPException`。

### 今天第一次出现、我全部当场给了的东西

这张表就是「今天新学的」的完整清单，不多不少：

| 构件 | 第一次在哪 | 一句话 |
|---|---|---|
| `class X(BaseModel):` 的那个**括号** | 二 ① | 括号里是父类；`X()` 用的 `__init__` 是父类的（第二节 ④ 验过 `is` 为 `True`） |
| `__annotations__` | 二 ④ | 注解被记在这个本子上，光写不赋值什么都不会创建 |
| `model_fields` | 二 ④ | `BaseModel` 把注解翻译成的字段表 |
| `Field(min_length=…, ge=…)` | 四 ① | 约束和默认值写在这儿 |
| `model_dump()` | 二 ③ | 模型 → dict，两个世界之间唯一的桥 |
| `list[类型]` | 四 ①（`tags`）、六 ①（`lines`、`batch`） | 元素类型也进注解，报错会带下标 |

| `loc` 里的**裸整数** | 四 ③ 第 10 条、六 ③ 第 5 条 | 那是下标，不是键名 |
