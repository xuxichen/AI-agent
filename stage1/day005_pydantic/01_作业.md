## 第 1 题 · 补完 Day 2 那张表

**做什么**：先凭记忆填下表，再运行验证。

| 写法 | `tags = []` 的结果 | 什么时候发现 |
|---|---|---|
| 普通 `class` | | |
| `@dataclass` | | |
| `pydantic.BaseModel` | | |

验证：

```bash
uv run python - <<'PY'
from dataclasses import dataclass, field
from pydantic import BaseModel

class Plain:
    tags = []

@dataclass
class DC:
    tags: list = field(default_factory=list)

class PM(BaseModel):
    tags: list[str] = []

p1, p2 = Plain(), Plain()
p1.tags.append("x"); print("普通类:", p1.tags, p2.tags)

d1, d2 = DC(), DC()
d1.tags.append("x"); print("dataclass:", d1.tags, d2.tags)

m1, m2 = PM(), PM()
m1.tags.append("x"); print("Pydantic:", m1.tags, m2.tags)

try:
    @dataclass
    class Bad:
        tags: list = []
except ValueError as e:
    print("dataclass 直接给 [] :", e)
PY
```

**验收结果**：

```
普通类: ['x'] ['x']
dataclass: ['x'] []
Pydantic: ['x'] []
dataclass 直接给 [] : mutable default <class 'list'> for field tags is not allowed
```

填表答案：

| 写法 | 结果 | 什么时候发现 |
|---|---|---|
| 普通 `class` | **共享** | 最晚，多实例时才暴露 |
| `@dataclass` | 用 `field(default_factory=list)` 才**隔离**；直接给 `[]` **定义时报错** | 最早，import 就炸 |
| `BaseModel` | 直接给 `[]` 就**隔离** | 不需要发现，它替你办了 |

**过关标准**：你能说出 Pydantic 隔离的机制——**默认值只在定义时创建一次，
但每次实例化都深拷贝一份**。不是「每次求值」（那是 JS），也不是「禁止」（那是 dataclass）。

## 第 2 题 · 主产物：`models.py`

**做什么**：在 `stage1/day005_pydantic/` 下新建 `models.py`，满足这份契约。

**三个模型**：

| 模型 | 字段 | 说明 |
|---|---|---|
| `NoteIn` | `title: str = Field(min_length=1, max_length=50)`、`tags: list[str] = []` | **不得有 `id`** |
| `Note` | `id: int`、`title: str`、`tags: list[str] = []`、`owner: str = "secret-owner"` | 内部全量模型 |
| `NoteOut` | `id: int`、`title: str`、`tags: list[str]` | **不得有 `owner`** |

**两个端点**（返回的对象完全一样，只有声明不同）：

| `POST /notes` | 请求体 `NoteIn` + `response_model=NoteOut` | 正常写法，`owner` 被过滤掉 |
| `POST /notes/leaky` | 请求体 `NoteIn`，**不写** `response_model` | 对照组，`owner` 泄露出去 |

两个端点的内部逻辑都是：


**末尾** `if __name__ == "__main__":` 用 `TestClient` 打印两行对比：


## 第 3 题 · 一次报出全部错误

**做什么**：故意传三个都错的字段，看 Pydantic 报几个错。

```bash
uv run python - <<'PY'
from pydantic import BaseModel, Field, ValidationError

class Note(BaseModel):
    id: int
    title: str = Field(min_length=1, max_length=50)
    tags: list[str] = []

try:
    Note(id="abc", title="", tags="nope")
except ValidationError as e:
    print("错误数:", e.error_count())
    for err in e.errors():
        print(" ", err["type"], err["loc"], "|", err["msg"])
PY
```

**验收结果**（本机实测）：

```
错误数: 3
  int_parsing ('id',) | Input should be a valid integer, unable to parse string as an integer
  string_too_short ('title',) | String should have at least 1 character
  list_type ('tags',) | Input should be a valid list
```

**三个要点，缺一个就没过关**：

1. **错误数是 3 不是 1** —— Pydantic 收集全部错误再抛，不是遇错即停
2. `loc` 是**元组** `('id',)`，嵌套模型时会变长（如 `('author', 'name')`）
3. 这套结构和 Day 4 的 422 `detail` **完全同源** —— FastAPI 就是把 `e.errors()` 塞进去

**加分验证**：把 `tags="nope"` 改成 `tags=["a", 1]`，看错误里的 `loc` 变成什么。
预期是：

```
嵌套 loc: string_type ('tags', 1)
```

两个收获：

1. `loc` 是 `('tags', 1)`——**它精确指出了列表里第几个元素错了**。
   这个能力在你 Day 18 处理文档切分结果时会很有用。
2. 错误类型是 `string_type`：`tags: list[str]` 收到 int `1`，Pydantic **没有**把它转成 `"1"`。
   但第 6 题里 `xs: list[int]` 收到 `"2"` 却**会**转成 `2`。这个不对称是故意的，
   原因在 `02_答案.md` 第 6 题。

## 第 5 题 · 费曼任务：为什么要三个模型

**做什么**：向同事解释——**为什么一个 `Note` 资源要写 `NoteIn` / `Note` / `NoteOut`
三个模型，不能一个走到底。不超过 4 句。**

```
1.
2.
3.
4.
```

**验收结果**——对照这 4 条：

1. 说清 `NoteIn` 是**入口**：只包含用户**能**提供的字段
2. 举出具体字段：`id` 不在 `NoteIn` 里，否则用户能指定 id 覆盖别人的记录
3. 说清 `NoteOut` 是**出口**：只包含用户**该**看到的字段，
   举出 `owner` / `password_hash` 这类不该出去的
4. 点出 `response_model` 的额外收益：**OpenAPI 文档同步收敛**，前端压根看不到那些字段

**自测**：同事反问「那我一个模型加上 `exclude` 参数不就行了」，你要能答：
那样**每个端点都要记得加**，而 `response_model` 是声明式的、写在签名上、
漏写会导致文档和实际响应不一致——防线要放在**不容易忘**的地方。

## 第 6 题 · 强制转换的边界在哪

**做什么**：先预测每行的结果（转换成功 / 报什么错），再运行。

```bash
uv run python - <<'PY'
from pydantic import BaseModel, ValidationError

class M(BaseModel):
    n: int
    xs: list[int]
    flag: bool

cases = [
    dict(n="7",   xs=[1, "2"], flag="yes"),
    dict(n="abc", xs=[1, 2],   flag=True),
    dict(n=7.9,   xs=[1, 2],   flag=1),
    dict(n=7,     xs="nope",   flag=False),
]
for c in cases:
    try:
        m = M(**c)
        print(f"{str(c):52} → OK  n={m.n!r} xs={m.xs!r} flag={m.flag!r}")
    except ValidationError as e:
        print(f"{str(c):52} → ERR {e.errors()[0]['type']} @ {e.errors()[0]['loc']}")
PY
```

**验收结果**（先自己预测，再对）：

```
{'n': '7', 'xs': [1, '2'], 'flag': 'yes'}                → OK  n=7 xs=[1, 2] flag=True
{'n': 'abc', 'xs': [1, 2], 'flag': True}                 → ERR int_parsing @ ('n',)
{'n': 7.9, 'xs': [1, 2], 'flag': 1}                      → ERR int_from_float @ ('n',)
{'n': 7, 'xs': 'nope', 'flag': False}                    → ERR list_type @ ('xs',)
```

**第 3 行是本题的陷阱**：很多人（包括我写这份作业的第一稿）会以为 `7.9` 被截断成 `7`。
**Pydantic 拒绝了它**，错误码 `int_from_float`。
但第 1 行的 `"7"` 却被接受并转成了 `7`。

**这两个都是「类型不符」，凭什么一个宽容一个严格？** 这就是本题要你回答的。

```
   答：

2. 为什么 n="7" 接受而 n=7.9 拒绝？两者的区别在哪？
   答：
```
