## 第 1 题 · 两个 out 模型 + 一个参数

### 判据（一句话一条）

1. `password` 会不会出现，**不取决于你 `return` 了什么，取决于 out 模型里写了什么**。
2. 嵌套的 `list[PublicUser]` 会**一层一层各自过滤**，不是只过滤最外层。
3. `age` 出来是 `null` 还是 `0`，**是你在 `PublicUser` 里写的那个默认值说了算**。

### 参考实现

和教案第八节比，只多了两个类和一个参数，函数体一字未动：

```bash
cd stage1/day005_pydantic
cat > code/python/hw01_users.py <<'PY'
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()


class UserIn(BaseModel):
    username: str = Field(min_length=3)
    password: str = Field(min_length=6)
    age: int | None = None


class PublicUser(BaseModel):
    username: str
    age: int | None = None


class UserListOut(BaseModel):
    count: int
    users: list[PublicUser]


users = []


@app.get("/")
def root():
    return {"service": "day005"}


@app.post("/signup")
def signup(payload: UserIn):
    for u in users:
        if u["username"] == payload.username:
            return {"error": "用户名已存在", "username": payload.username}
    rec = payload.model_dump()
    users.append(rec)
    return {"ok": True, "stored": rec}


@app.get("/users", response_model=UserListOut)
def list_users():
    return {"count": len(users), "users": users}
PY
```

`PublicUser` 里那个 `age: int | None = None` 有两个人在做：
`| None` 让 `null` 合法（第六节 ⑤），`= None` 让它**不进 `required`**（第四节 ⑤）。
你要是写成 `age: int = 0`，第 3 条就会回来 `"age": 0`——**第七节 ⑤ 那张表的「补默认值」那一行**。

```bash
curl -s -w ' [%{http_code}]\n' -X POST -H 'content-type: application/json' -d '{"username":"abc","password":"123456"}' http://127.0.0.1:8751/signup
curl -s -w ' [%{http_code}]\n' http://127.0.0.1:8751/users
curl -s -w ' [%{http_code}]\n' -X POST -H 'content-type: application/json' -d '{"username":"zzz","password":"123456","age":3}' http://127.0.0.1:8751/signup
curl -s -w ' [%{http_code}]\n' http://127.0.0.1:8751/users
```

真跑：

```
{"ok":true,"stored":{"username":"abc","password":"123456","age":null}} [200]
{"error":"用户名已存在","username":"abc"} [200]
{"count":1,"users":[{"username":"abc","age":null}]} [200]
{"ok":true,"stored":{"username":"zzz","password":"123456","age":3}} [200]
{"count":2,"users":[{"username":"abc","age":null},{"username":"zzz","age":3}]} [200]
```

`password` 在第 3、5 条**一个字符都没有**，而 `stored` 里那条 `rec` 是完整的——
**库里躺着的东西和你被允许看到的东西，从今天起是两回事。**

### 两问的答案

1. 第 2 条撞上了函数里那个 `for` 循环：`users` 里已经有 `abc`，于是走了
   `return {"error": ...}` 这一支，`return` 的形状和成功那次**不一样**，但状态码都是 200。
   前端只能写 `if (data.error)`——**这就是它骗人的地方**：`error` 这个键名是你随口起的中文，
   换一个接口叫 `msg`，前端就得再记一遍。Day 6 用 `HTTPException` 把它换成状态码。
2. 因为**这次那个默认值是 `None`，不是我猜的 `0`**。
   第七节补的是「out 模型里写的那个默认值」，你在 `PublicUser` 里写的是 `= None`。
   而且这里还有一层：存进去的 `rec` 本来就有 `"age": null`（第八节 ⑤ 第一条：
   「不给」和「给 `null`」在 dump 之后长得一模一样），所以它连补都不用补。

## 第 2 题 · `hw02_book.py`

### 参考实现

```bash
cd stage1/day005_pydantic
cat > code/python/hw02_book.py <<'PY'
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()


class BookIn(BaseModel):
    title: str = Field(min_length=2)
    pages: int = Field(ge=0)
    tags: list[str] = []
    author: str | None = None


class BookOut(BaseModel):
    id: int
    title: str
    tags: list[str]


books = []


@app.post("/books", response_model=BookOut)
def add_book(payload: BookIn):
    data = payload.model_dump()
    data["id"] = len(books) + 1
    books.append(data)
    return data


@app.get("/books")
def list_books():
    return books
PY
```

### 五个先猜的答案

| 条 | 状态码 | 响应里有几个键 | 是什么 |
|---|---|---|---|
| 1 | 200 | **3** | `id`、`title`、`tags` |
| 2 | 200 | 3 | 同上，`tags` 是 `[]` |
| 3 | 422 | — | `string_too_short`，`ctx` 里 `min_length: 2` |
| 4 | 422 | — | `greater_than_equal`，`ctx` 里 `ge: 0` |
| 5 | 200 | 每项 **5** | `title`、`pages`、`tags`、`author`、`id` |

### 两个必答的答案

1. **`response_model=BookOut` 删的**，时刻是**你的函数 `return` 之后、字节发出去之前**。
   库里存的永远是 `data`（`payload.model_dump()` 再补一个 `id`）那**五个键**，
   所以 `/books` 不写 `response_model` 就会把 `pages`、`author` 原样吐出来。
   **这一条本身就是第 1 题的那个 `/users` 和 `/users-raw` 的关系。**
2. **不是同一个对象。** 那个答案在第四节 ④ 的 `05_mutable_default.py` 里：
   `m1.tags is m2.tags = False`——`BaseModel.__init__` 在没收到这个字段时**复制一份新的**。
   所以第 5 条里那两项各自的 `tags` 是两个不同的 list，改一个不动另一个。
   函数参数那个 `def f(acc=[])` 才是真共享（同一个对象，三次越滚越长）。

## 第 3 题 · 六条，四种判据

| # | 状态码 | 谁的错 | 要改什么 | 出处 |
|---|---|---|---|---|
| 1 | 422 | **他的** | body 里补上 `addr`（而且得是个对象） | 六 ③ 第 2 条 |
| 2 | **500** | **你的** | `UserOut` 有必填 `age`，`/short` return 的 dict 没有它 | 七 ④ 第一条 |
| 3 | 422 | 他的 | `tags` 的**第 0 个元素**给成了整数，改成 `"1"` | 四 ③ 第 10 条 |
| 4 | **500** | **你的** | 代码把模型当 dict 用（`it["price"]`），改成 `.` 或先 `model_dump()` | 五 ④ |
| 5 | 422 | 他的 | body 没错，**请求头缺 `content-type: application/json`** | 九 ④ 第 12 条 |
| 6 | 422 | 他的，但**规矩是你定的** | 密码给成 `"123"`，`min_length=6` 是你自己写进 `Field` 的 | 八 ③ 第 3 条 |

### 两个必答的答案

1. **第 2 条和第 4 条。** 客户端收到的都是同一句 `Internal Server Error` + 500，
   **一条 `detail` 都拿不到**——那两段信息只写进了你自己的终端 A。
   这就是为什么第七节说「500 是只给你自己看的报错」。
2. **判据本身没有例外**：六条里凡是 `loc` 首词是 `body` 的都 422，是 `response` 的都 500。
   但有两处要补清楚：
   - **第 3 条的 `loc` 是三个词**：`body`（从他的 body 读的）→ `tags`（哪个字段）→
     `0`（那个 list 的**第 0 个元素**）。
     **第一个词只回答「从哪儿读到」，位置在后头的词里。**
   - **第 4 条根本没有 `loc`**。它是你代码里的 Python 异常，FastAPI 没参与判断，
     所以它给你的是**文件名 + 行号**，不是 `loc`。
     `loc` 只存在于 FastAPI 自己生成的那些报错里。

## 第 4 题 · 两个 bug，一个在门口响，一个在出门响

### 4.1 第一个 bug：`FolderIn.notes` 声明成了 `list[str]`

```python
class FolderIn(BaseModel):
    name: str = Field(min_length=2)
    notes: list[str] = []        # ← 应该是 list[NoteIn]
```

**改法：把 `str` 换成你自己写的那个类 `NoteIn`。** 第六节 ① 的 `lines: list[Address]` 就是这个形状。

为什么第 2、5 条的 `loc` 停在 `["body","notes",0]` 就断了？
因为它只查到「第 0 个元素不是 `str`」，**它压根不知道里面还有 `text` 和 `labels` 这两个键**——
`list[str]` 的字段表里没有它们。所以 `input` 老老实实把整个 dict 印给你看（第三节那条 `missing` 规矩）。

**而第 3 条 `{"name":"play"}` 是 200。** `notes` 有默认值 `[]`，一个字都没查——
**这就是为什么第一个 bug 平时不响，只有带 notes 的请求才炸。**

### 4.2 改完的整份文件（存成 `hw04_notes_fixed.py`，端口 8754）

两处改动，都在类定义里，我用注释标出来了：

```bash
    edited: bool = False              # ← 修 2：必填字段没人给它，就得给个默认值

@app.get("/folders/{fid}")
```

**进门通了，出门被拦下。** `loc` 的第一个词是 `response`（第七节那条判决书），
`input` 里那个 `{'text': 'write hw', 'labels': ['a']}` 就是你 `model_dump()` 出来的那条 note——
**`NoteIn` 里没有 `edited`，所以没人给它，而 `NoteOut` 说它必填。**

所以「接口回了 500」从来不等于「什么都没发生」。

### 4.4 三条问答的答案

1. **没进。** 第 2、5 条是 422，Pydantic 在**进函数之前**就把请求挡了，
   `add_folder` 连一次都没被调用，`folders` 当然没动——第 6 条里只有第 3 条那条 `play`。
   对照 4.3：改成 500 就**进了**。**同一个接口，422 不留痕，500 留痕。**
2. 多出来的那个键是 `edited`，**`NoteOut` 给它补的默认值 `False`**（第七节 ⑤ 表第二行）。
   而 `GET /folders` 里同一条没有它，因为**库里存的 `data` 是 `payload.model_dump()` 的结果**，
   `NoteIn` 没写 `edited`，dump 就不可能有它。
   **`response_model` 补的值只活在响应里，一次都没进过你的数据。**
   这句话以后做「字段是算出来的还是存出来的」那类题时会反复用到。
3. `HTTPException`。Day 6 第一节。

### 4.5 这一题最可能被写错的三处

1. **把修 1 改成 `notes: list[dict]`。** 它能跑，但**字段表就没了**：
   `text` 的长度约束、`labels` 的类型、下标报错，全部消失（第四节那条 `isAdmin` 的规矩——
   `dict` 什么都收）。**今天学的全部东西就白学了。**
2. **把修 2 改成把 `edited` 从 `NoteOut` 里删掉。** 也能跑，但那是**改考卷**不是答题：
   你要么留下这个字段并给它默认值，要么明说它不该出现在响应里——
   这一处没有标准答案，但**你得能说出你选的是哪一种**。
3. **在函数里去 `data["edited"] = False` 补。** 这不是 Pydantic 的错，可它绕开了这一题的机关：
   out 模型的默认值本来就在替你干这件事，而且它只在响应上生效、不污染数据（4.4 第 2 问）。

## 今天可带走的四句

1. **进门看 `body`，出门看 `response`。** 422 是他的错，他会自己改；500 是你的错，他只能重试。
2. **`loc` 是一条路径**：字符串是键名，裸数字是下标。它报几个词，取决于你的模型有几层。
3. **模型不是 dict**：函数里用 `.`，要长期存就先 `model_dump()`；
   `response_model` 补的键**不会**进你的数据。
4. **500 不等于「什么都没发生」**：`return` 之前的副作用已经落下去了。
   今天你为了找 422 学过读 `loc`，明天开始你要为了 500 学着读**栈**。
