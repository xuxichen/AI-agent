## 第 1 题 · 五个形状，哪一个「用了 gather 其实没并发」（16 分钟）

这五段代码每个都用了 `await`、`create_task`、`gather` 里的至少一样。
**其中三个是真并发，两个不是。** 你的任务是先把五个耗时写下来，再跑。

### ① 建文件

```bash
cd stage1/day003_async
cat > code/python/hw01_shapes.py <<'PY'
import asyncio
import time


async def job(name, sec):
    await asyncio.sleep(sec)
    return name


async def sleepy(name, sec):
    time.sleep(sec)
    return name


def blocked(name, sec):
    time.sleep(sec)
    return name


async def s1():
    return await asyncio.gather(job("甲", 0.2), job("乙", 0.2))


async def s2():
    a = await job("甲", 0.2)
    b = await job("乙", 0.2)
    return [a, b]


async def s3():
    t = asyncio.create_task(job("甲", 0.2))
    mid = await job("插队", 0.1)
    first = await t
    return [first, mid]


async def s4():
    return await asyncio.gather(sleepy("甲", 0.2), sleepy("乙", 0.2))


async def s5():
    return await asyncio.gather(
        asyncio.to_thread(blocked, "甲", 0.2),
        asyncio.to_thread(blocked, "乙", 0.2),
    )


async def main():
    start = time.perf_counter()
    res = await s1()
    print(f"形状 1  gather 两个             -> {time.perf_counter() - start:.2f}s | 返回 {res}")

    start = time.perf_counter()
    res = await s2()
    print(f"形状 2  逐个 await              -> {time.perf_counter() - start:.2f}s | 返回 {res}")

    start = time.perf_counter()
    res = await s3()
    print(f"形状 3  登记完再去睡自己的      -> {time.perf_counter() - start:.2f}s | 返回 {res}")

    start = time.perf_counter()
    res = await s4()
    print(f"形状 4  gather 但里面 time.sleep -> {time.perf_counter() - start:.2f}s | 返回 {res}")

    start = time.perf_counter()
    res = await s5()
    print(f"形状 5  to_thread 配 gather     -> {time.perf_counter() - start:.2f}s | 返回 {res}")


asyncio.run(main())
PY
cd ../..
```

三个名字先说清楚，不然后面没法读：

| 名字 | 是什么 | 你哪儿见过 |
|---|---|---|
| `job` | `async def`，里面是 `await asyncio.sleep` —— **会给出控制权**的那种等 | 第二节 |
| `sleepy` | `async def`，里面是 `time.sleep` —— **不给**的那种等 | 第六节的 `using_time_sleep` |
| `blocked` | **普通 `def`**，里面也是 `time.sleep` —— 第六节那个病，但外面套了 `to_thread` | 第七节的 `blocked_work` |

**`main` 自己是逐个 `await s1()`…`await s5()` 的**——这是故意的。
五个测量必须排队做，不然你量到的是它们叠在一起的时间。

### ② 先猜再跑（**这一格不填，这题等于没做**）

```
形状 1  gather 两个              我猜 ____ s | 我猜返回 ____________
形状 2  逐个 await               我猜 ____ s | 我猜返回 ____________
形状 3  登记完再去睡自己的        我猜 ____ s | 我猜返回 ____________
形状 4  gather 但里面 time.sleep  我猜 ____ s | 我猜返回 ____________
形状 5  to_thread 配 gather       我猜 ____ s | 我猜返回 ____________
```

猜完再跑：

```bash
uv run python stage1/day003_async/code/python/hw01_shapes.py
```

### ③ 真实输出

```
形状 1  gather 两个             -> 0.20s | 返回 ['甲', '乙']
形状 2  逐个 await              -> 0.40s | 返回 ['甲', '乙']
形状 3  登记完再去睡自己的      -> 0.20s | 返回 ['甲', '插队']
形状 4  gather 但里面 time.sleep -> 0.41s | 返回 ['甲', '乙']
形状 5  to_thread 配 gather     -> 0.21s | 返回 ['甲', '乙']
```

### ④ 对上

**没猜错的形状，比你猜对的更值得看。** 下面按「最容易猜错」排。

**形状 4：0.41s。它用了 `gather`，一点没并起来。**
`gather` 确实把两个任务都登记了，循环也确实去跑了第一个——
然后 `time.sleep(0.2)` 霸住那个唯一的线程不撒手（第三节末尾那句话）。
两个 0.2 摞起来 = 0.4。这正是第六节 B 段的三倍缩版。
**「我用了 gather」不等于「我并发了」——这一条你以后每天都会用到。**

**形状 3：0.20s。它一个 `gather` 都没用，却是并发的。**
`t = asyncio.create_task(...)` 一登记，甲的 0.2 秒倒计时就开始了。
接着 `await job("插队", 0.1)` 交出控制权，循环切给甲。
插队睡完 0.1，甲还剩 0.1；`await t` 等完那 0.1。
总共 = 甲的 0.2，**插队那 0.1 完全藏在里面**。
第二节 A 段是「三个 await 排着写」，这里是「两个 await 排着写但中间那个是被登记过的」——
差的就是那一行 `create_task`。

**形状 2：0.40s。五段里唯一一行都没写错的，也是最慢的。**
`a = await job(...)` 单独看每个都对，排在一起就是第二节 A 段。

**形状 5：0.21s。** `blocked` 里的 `time.sleep` 一个字没改，
但 `to_thread` 把它挪去了别的线程，两个线程同时睡（第七节 B 段）。

**返回列表那一列，五个形状没有一个按「谁先睡完」排**：
形状 3 明明是 `插队` 先醒，返回的是 `['甲', '插队']`——甲是**先登记**的那个。
这是第四节的结论在 `create_task` 上也成立：**跟着登记的先后，不跟着完成的先后。**

## 第 3 题 · 四个不同长度，先算出来再跑（10 分钟）

前两道题里所有的等待都一样长。这题换成 **0.4 / 0.1 / 0.2 / 0.3 四个不同的长度**，
你就没法再靠「反正都一样」猜了——**必须算**。

### ① 建文件

```bash
cd stage1/day003_async
cat > code/python/hw03_ratio.py <<'PY'
import asyncio
import time


async def order(name, sec):
    await asyncio.sleep(sec)
    return name


async def melt(name, sec):
    time.sleep(sec)
    return name


async def main():
    start = time.perf_counter()
    a = await asyncio.gather(
        order("甲", 0.4), order("乙", 0.1), order("丙", 0.2), order("丁", 0.3)
    )
    ta = time.perf_counter() - start

    start = time.perf_counter()
    b = await asyncio.gather(
        melt("甲", 0.4), melt("乙", 0.1), melt("丙", 0.2), melt("丁", 0.3)
    )
    tb = time.perf_counter() - start

    start = time.perf_counter()
    c = await asyncio.gather(
        melt("甲", 0.4), order("乙", 0.1), melt("丙", 0.2), order("丁", 0.3)
    )
    tc = time.perf_counter() - start

    print(f"A 四个 await asyncio.sleep : {ta:.2f}s | 返回 {a}")
    print(f"B 四个 time.sleep          : {tb:.2f}s | 返回 {b}")
    print(f"C 两个各带一半             : {tc:.2f}s | 返回 {c}")
    print(f"比值 C 除以 A              : {tc / ta:.2f}")


asyncio.run(main())
PY
cd ../..
```

三段用的就是同那四个 `("甲", 0.4)`、`("乙", 0.1)`、`("丙", 0.2)`、`("丁", 0.3)`，
`gather` 也一模一样。**只有函数体里那一行不一样。**

### ② 先算（**算不出就不许跑**）

```
A = ____ s      我是怎么算的：____________________
B = ____ s      我是怎么算的：____________________
C = ____ s      我是怎么算的：____________________
比值 C ÷ A = ____
```

C 那格是这题的全部。**先排除两个诱人的错答案**：
不是 `max = 0.40`（甲没让出线程，后面三个不能跟它重叠），
也不是 `求和 = 1.00`（乙那 0.1 是压在丙睡觉的那段里的，没占额外时间）。

### ③ 真实输出

```
A 四个 await asyncio.sleep : 0.40s | 返回 ['甲', '乙', '丙', '丁']
B 四个 time.sleep          : 1.00s | 返回 ['甲', '乙', '丙', '丁']
C 两个各带一半             : 0.91s | 返回 ['甲', '乙', '丙', '丁']
比值 C 除以 A              : 2.27
```

### ④ 对上——C 那 0.90 秒是这么攒出来的

关键在第三节那句话的另一半：**登记只是排进队伍，函数体要等轮到它才开始跑。**

下面这个时间线不是我推的，是我给四行都插上打印、在你这台机器上跑出来的真东西：

```
t = 0.00   甲拿到线程。它是 melt，time.sleep(0.4)，不交出去
t = 0.40   甲完。乙这才第一次拿到线程
t = 0.40   乙：await asyncio.sleep(0.1)，说好 0.50 醒。交出去
t = 0.40   丙紧接着拿到线程。time.sleep(0.2)，不交出去
t = 0.60   丙完。乙的 0.50 早就到了，可是没人叫它
t = 0.60   丁这才第一次拿到线程：await asyncio.sleep(0.3) → 0.90 醒
t = 0.90   乙和丁都完了
```

**甲 + 丙 + 丁 = 0.4 + 0.2 + 0.3 = 0.90**，乙那 0.1 一秒都没多出来。
（实跑是 0.91，多的那 0.01 是每次调度和打印的耗时间，跟第七节量到 0.61 而不是 0.60 同一个原因。）

`t = 0.60` 那一行还藏着一件更小的事：**乙的闹钟 0.50 就响了，但它 0.60 才跑。**
到点不算，得轮到它。线程被丙按住的那 0.1 秒，乙就只能躺着。

所以 `melt` 卡在队列里的时候，**它不只按住自己，它把排在它后面的所有人的起跑线都往后推。**
这就是为什么第六节说一个 `time.sleep` 能把整份 async 代码清零——
它伤害的不是它自己那一段，是**排在它后面的所有人**。

### ⑤ 只改一行，先算新的 C，再跑

把 C 段里那一处的 `melt` 换成 `order`：

```python
    c = await asyncio.gather(
        melt("甲", 0.4), order("乙", 0.1), order("丙", 0.2), order("丁", 0.3)
    )
```

甲还是阻塞的，可丙不再按住线程了。**先写下你认为的新 C，再跑。**

```
A 四个 await asyncio.sleep : 0.40s | 返回 ['甲', '乙', '丙', '丁']
B 四个 time.sleep          : 1.00s | 返回 ['甲', '乙', '丙', '丁']
C 两个各带一半             : 0.70s | 返回 ['甲', '乙', '丙', '丁']
比值 C 除以 A              : 1.76
```

新的 0.70 = **甲的 0.4，加上乙丙丁同时数完的最长那个 0.3**。
丙一改好，乙丙丁三个人的起跑线就都齐了（都在 0.40），于是它三个叠成一段。
**这就是第二节的 B 段，只不过前面多压了 0.4 秒。**

跑完记得把这一行改回 `melt`。**新 C 的 0.70 你是先算出来还是跑出来才想到的，
这题的第 3 个自批格子就照实填。**

## 第 4 题 · 主产物：`code/python/batch_slow.py`（22 分钟）

大纲要的「并发跑一批任务的脚本」，但**一个网络请求都不发**。
**从空白写**，不许抄今天任何一段实验代码——名字也要换（用你自己的话命名，别叫 `s1`）。

### 七条要求

| # | 要求 |
|---|---|
| 1 | `async def make_coffee(name, sec)`：印 `   {name} 开始冲`，`await asyncio.sleep(sec)`，印 `   {name} 冲好了`，`return name` |
| 2 | `async def serial()`：把三个 `make_coffee`（都 0.3s）**挨着 `await`**，`return` 它花掉的秒数 |
| 3 | `async def concurrent()`：**`gather`** 同样三个 0.3s，`return` 它花掉的秒数 |
| 4 | 印成这一行，格式照抄：`print(f"串行 {s:.2f}s | 并发 {c:.2f}s | 比值 {c / s:.2f}")` |
| 5 | 一个函数里 `gather` 三个**不同耗时**的 `make_coffee`，印 `返回顺序: [...]`，值必须是 **`[2, 0, 1]`** |
| 6 | 一个**普通 `def`**（不是 `async def`）里面用 `time.sleep`；把**它**交给 `to_thread` 跑两次，`gather` 起来，印 `两个 to_thread 花掉 {…:.2f}s` |
| 7 | 驱动整个脚本的那几行包在 `if __name__ == "__main__":` 里 |

要求 5 的 `[2, 0, 1]` 是这么来的：三个任务的 `name` 分别传 `2`、`0`、`1`（就是列表里的数字），
耗时要**不一样**且**最快的那个排在中间**。你只要按 `2, 0, 1` 的顺序传，
不管它们谁先跑完，`gather` 回来的就是 `[2, 0, 1]`。**故意别让耗时和名字同序**，
这样你才看得出自己在不在偷看完成顺序。

### 该看到

```
   甲 开始冲
   甲 冲好了
   乙 开始冲
   乙 冲好了
   丙 开始冲
   丙 冲好了

   甲 开始冲
   乙 开始冲
   丙 开始冲
   甲 冲好了
   乙 冲好了
   丙 冲好了

串行 0.90s | 并发 0.30s | 比值 0.33

   2 开始冲
   0 开始冲
   1 开始冲
   0 冲好了
   1 冲好了
   2 冲好了
返回顺序: [2, 0, 1]

两个 to_thread 花掉 0.20s
```

**逐段对上**：第一段严格「开始—好了」交替 = 串行；第二段六个名字分成两批 = 并发；
`比值 0.33` 就是 0.30 ÷ 0.90；
第三段那六行**完成顺序是 0、1、2，返回却是 `[2, 0, 1]`**——这是要求 5 的验收点，
你如果返回了 `[0, 1, 2]`，说明你按谁先跑完去收集了（红在第 4 项）。

| **只有 5** | 把那个阻塞函数改成了 `async def` | `✗ 5. ... 这些 async def 里面有 time.sleep：['chop']。…` |
| **只有 5（另一种）** | 全文没有一个普通 `def` 里面是 `time.sleep` | `✗ 5. ... 没有任何**普通 def**（不是 async def）里面用了 time.sleep。要求 6 要的就是一个你改不动的阻塞函数，把它调给 to_thread` |
| **2、3、4、6 四项** | 开关里没写 `asyncio.run(main())`，整个脚本一行都没跑 | `✗ 2. 输出三行可解析 —— 缺：串行/并发/比值那行…；顺序那行…；to_thread 那行…`<br>`✗ 6. ... 开关里面没有 asyncio.run —— 整个脚本的入口应该长这样：if __name__ == "__main__":` |

最后三行别混着看，三种病因：

- **`async def` 里冒出 `time.sleep`** → 它自己成了阻塞源，红的是第 5 项的第一句。
- **全文一个普通 `def` 里的 `time.sleep` 都没有** → 没有阻塞函数可丢给线程，红的是第 5 项的第二句。
- **开关里没写 `asyncio.run`** → 注意**第 1 项是绿的**（退出码确实是 0）。
  它不崩，它只是**什么都没干**。

**最该看一眼的是「1、2、3、4、6 五项」那一格。** 你在协程里调 `asyncio.run`，
脚本第一秒就崩了，于是六项里有五项同时红——**红的项数不代表你错了五处，
代表你错的那一处把整个脚本拦在了门口。** 那种情况下**只看第 1 项**，
其余四项的报错都是在复述「你一行都没印出来」。
