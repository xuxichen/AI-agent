## 第 1 题 · 先预测，再运行

**做什么**：**不要运行**，先写下你认为两段的耗时。

```bash
uv run python - <<'PY'
import asyncio, time

async def slow():
    await asyncio.sleep(0.15)

async def a():
    t = time.perf_counter()
    await slow(); await slow()
    print(f"A 逐个 await: {time.perf_counter() - t:.2f}s")

async def b():
    t = time.perf_counter()
    t1 = asyncio.create_task(slow())
    t2 = asyncio.create_task(slow())
    await t1; await t2
    print(f"B create_task: {time.perf_counter() - t:.2f}s")

async def main():
    await a(); await b()

asyncio.run(main())
PY
```

**验收结果**：

```
A 逐个 await: 0.30s
B create_task: 0.15s
```

你的预测必须是 **A ≈ 0.30、B ≈ 0.15**（±0.03s 浮动正常）。

**如果 A 也是 0.15**：说明你以为 `await` 会开启并发。回教案「学习目的」那一段——
`await` 是**当场等完**，并发只来自 `create_task` / `gather` 的登记动作。

## 第 3 题 · 忘记 await 的下场，并和 JS 对照

**做什么**：

```bash
uv run python - <<'PY'
import asyncio

async def slow():
    await asyncio.sleep(0.1)
    print("我被执行了")

async def main():
    slow()          # 故意不 await

asyncio.run(main())
print("main 正常结束")
PY
echo "退出码 $?"
```

**验收结果**：

```
main 正常结束
/path/to/python:6: RuntimeWarning: coroutine 'slow' was never awaited
RuntimeWarning: Enable tracemalloc to get the object allocation traceback
退出码 0
```

三个要点，缺一个就没过关：

1. **`我被执行了` 没有打印** —— 协程压根没跑
2. **退出码是 0** —— 这不是错误，只是 warning
3. `main 正常结束` 排在 warning **前面** —— warning 是在协程对象被 GC 时才发出的

**JS 对照**：

```bash
node -e '
async function slow() { await new Promise(r => setTimeout(r, 100)); console.log("我被执行了"); }
async function main() { slow(); }
main().then(() => console.log("main 正常结束"));
'
```

预期：**`我被执行了` 会打印**（Promise 一创建就开始跑），顺序在 `main 正常结束` 之后。

这就是教案里那句「Python 的 coroutine 是惰性的，JS 的 Promise 是立即执行的」的实证。
**结论**：在 Python 里，漏写 `await` 的后果比 JS 严重得多——JS 至少会把事办了，Python 是什么都没发生。

## 第 4 题 · gather 的异常语义

**做什么**：先预测两种调用各自的结果，再跑。

```bash
uv run python - <<'PY'
import asyncio

async def bad():
    raise ZeroDivisionError("除零")

async def ok():
    return 1

async def main():
    try:
        await asyncio.gather(bad(), ok())
    except Exception as e:
        print("默认:", type(e).__name__)

    res = await asyncio.gather(bad(), ok(), return_exceptions=True)
    print("return_exceptions:", [type(r).__name__ for r in res])

asyncio.run(main())
PY
```

**验收结果**：

```
默认: ZeroDivisionError
return_exceptions: ['ZeroDivisionError', 'int']
```

**JS 对照**：

```bash
node -e '
const bad = () => Promise.reject(new Error("除零"));
const ok  = () => Promise.resolve(1);
Promise.all([bad(), ok()]).catch(e => console.log("Promise.all:", e.constructor.name));
Promise.allSettled([bad(), ok()]).then(r => console.log("allSettled:", r.map(x => x.status).join(",")));
'
```

预期：`Promise.all: Error`、`allSettled: rejected,fulfilled`。

**这题要你写下来的结论**（一句话，写在下面）：
`return_exceptions=True` 对应 JS 的 `allSettled`，但**返回形状不同**——
JS 给你 `{status, value/reason}` 包装对象，Python 直接把异常实例塞进结果列表。
所以 Python 这边你必须自己 `isinstance(r, Exception)`，否则会拿异常当数据往下传。

## 第 5 题 · 费曼任务：3 句话

**做什么**：向只会 JS 的同事解释——**为什么 Python 里 `slow()` 不加 `await` 什么都没发生，
而 JS 里 `f()` 不加 `await` 已经在跑了。不超过 3 句。**

```

```

**验收结果**——对照这 3 条：

1. 说清 Python 调用 `async def` 只**构造一个 coroutine 对象**，不执行函数体
2. 说清执行要靠 `await` / `create_task` / `gather` 把它交给事件循环
3. 给出对照：**JS 的 Promise 是立即执行的**，`await` 只决定「在哪等结果」，不决定「跑不跑」

**自测**：同事反问「那 Python 怎么让它立刻开始跑」，你要能不假思索答 `asyncio.create_task()`。
