三个新面孔，一次说清：

| 写法 | 是什么 | 注意 |
|---|---|---|
| `try:` | 「下面这段可能出事，出事就别往下走，跳到 `except`」 | `try` 块里的代码**正常时照常跑**，它不是「安全区」 |
| `except KeyError as err:` | 「如果是 `KeyError` 这类，就跑我这段，把那个异常对象交给 `err`」 | 只有类型**对上**才跑；对不上就跳过整个 `except` |
| `raise ValueError("...")` | 「我现在就制造一个错，并且把它扔出去」 | `raise` 之后的代码**一行都不执行**，包括 `return` |

### ⑤ 对上

**第 1 条**：`4.` 没印。`read_key` 那一句一崩，控制流**立刻**离开 `try` 块，跳进对上的 `except`，`try` 里剩下的句子永远轮不到。
这就是「异常是一条捷径」：它不返回值，它直接改写你代码的执行顺序。

**第 2 条**：`'price'`，带引号。因为 `KeyError` 打印自己时用的是那个键的 `repr`（字符串就给你带上引号）。
`ValueError` 就没这待遇——第 9 条里 `err` 印出来是 `invalid literal for int() with base 10: 'abc'`，那是 `ValueError` 自己带的那句话。**同一个 `err`，不同类型的打印习惯不一样**，别拿 `err` 直接当业务文案用。

**第 3 条**：`6.` 印了。`except` 跑完，异常就被处理掉了，控制流回到 `try` 之后的正常位置继续往下。进程没死。

**第 4 条**：不执行。`raise` 那一句把 `return n` 的路挡死了。第 12 行抓到的就是 `raise` 带的那句话（`年龄不能是负数`），连 `ask_age` 这个名字都没出现在异常信息里。

**第 5 条（今天最重要的一条）**：返回 `-3`，**一声不响**。
`ValueError("年龄不能是负数")` 这一句的语义是「造一个 `ValueError` 对象，然后丢掉」。它和 `1 + 2` 不接返回值一样，什么后果都没有。
**异常必须被 `raise` 出去才算数。** 这句话是第二节那个手误的全部原理。

**第 6 条**：抓住了。`except` 后面写的名字是一个**范围**，不是一个精确类型：`Exception` 是所有常规异常的顶上那一层，`ValueError`、`KeyError`、`TypeError` 全在里面。
这条直接决定第四节 `@app.exception_handler(Exception)` 为什么能兜住一切——那行写的是同一个 `Exception`。

**第 7 条**：退出码 `1`，而且终端里留了一整段 `Traceback`。
`except KeyError` 对不上 `ValueError`，于是**没有任何一层接住它**，异常一路往上撞到进程外，进程当场死掉。
看那段栈的两帧：最后一帧 `line 70, in <module>` 是崩的位置，上面一帧 `line 6, in to_number` 是它从哪个函数里扔出来的——**昨天你只会读这种栈，今天你能决定它要不要发生。**

**顺手对上三件旧账**：

| 你前几天见过的崩法 | 类型 | 现在你知道它为什么是这一类 |
|---|---|---|
| `it["price"]`，而 `it` 是个模型对象（昨天第五节那个 500） | `TypeError` | 对象不支持方括号取值 |
| `int("abc")`（今天第 8 句） | `ValueError` | 类型是对的，值不对 |
| `store["没这个键"]`（今天第 3 句） | `KeyError` | dict 里没这个键 |

### ⑥ 这一节和 HTTP 有什么关系

你的端点函数里 `raise` 出来的东西，没人抓——**FastAPI 已经在最外面替你 `except` 了**。
它 `except` 完做的事就是你昨天看到的：给客户端一句 `Internal Server Error`，给自己一屏栈。

所以今天要学的不是「怎么在端点里写 try/except」，而是：

1. 怎么**主动扔一个能被框架听懂的异常**（第二节 `HTTPException`）；
2. 怎么**改写框架那个 `except` 干的事**（第四节处理器、第六节中间件）。

第一节那两条原理——「不 `raise` 等于什么都没发生」「`except 类型` 是个范围」——后面每一节都在用。

## 二、`HTTPException`：一个 `raise` 都不许省

### ① 建文件

```bash
cd stage1/day006_fastapi_advanced
cat > code/python/02_http_exception.py <<'PY'
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field

app = FastAPI()


class ItemIn(BaseModel):
    name: str = Field(min_length=2)
    price: float = Field(gt=0)


items = [
    {"id": 1, "name": "pen", "price": 3.0},
    {"id": 2, "name": "cap", "price": 5.0},
]


@app.get("/loose/{item_id}")
def read_loose(item_id: int):
    for it in items:
        if it["id"] == item_id:
            return it
    HTTPException(status_code=404, detail="没有这个 id")
    return {"error": "走到这一行，说明那句 HTTPException 什么都没干"}


@app.get("/strict/{item_id}")
def read_strict(item_id: int):
    for it in items:
        if it["id"] == item_id:
            return it
    raise HTTPException(status_code=404, detail="没有这个 id")


@app.get("/dict/{item_id}")
def read_dict(item_id: int):
    for it in items:
        if it["id"] == item_id:
            return it
    raise HTTPException(
        status_code=404,
        detail={"error": "没有这个 id", "item_id": item_id, "可用": [1, 2]},
    )


@app.get("/teapot")
def teapot():
    raise HTTPException(status_code=418, detail="我是一个茶壶")
PY
```

`/loose` 和 `/strict` 是同一个函数抄两遍，**只差第五行开头那个 `raise`**。
`HTTPException` 要读的新东西只有两个参数：

| 参数 | 去哪了 |
|---|---|
| `status_code=404` | 变成 HTTP 响应的状态码 |
| `detail="..."` | 变成响应体里 `{"detail": ...}` 那个值 |

`detail` 这个名字是框架写死的，不是你起的。昨天那个 `{"error": ...}` 里的 `error` 是你随口起的键名，
换一个接口起个 `msg`，前端就得再记一遍——**今天换成框架统一的名字。**

### ④ 手工实验：把 `raise` 摘掉再装回去

`/loose` 已经给你看了「不 `raise` 会怎样」。现在轮到 `/strict`——它和 `/loose` 唯一的差别就是最后有没有那句 `return`。

在 `02_http_exception.py` 里把 `/strict` 那个函数中的 `raise ` 删掉（只删这 5 个字母，后面那句原封不动），
存盘，**`Ctrl-C` 停掉服务重新起**，然后重打一条：

```bash
curl -s -w ' [%{http_code}]\n' http://127.0.0.1:8761/strict/99
```

```text
删掉 raise 之后：  null [200]
装回 raise 之后：  {"detail":"没有这个 id"} [404]
```

**和第一节第 5 条一模一样**：`HTTPException(...)` 只是造了个对象，没人扔它就等于没发生。
但这次多一层信息：`/strict` 删掉 `raise` 以后，`for` 循环走完、那行空转完、函数末尾没 `return` 就掉下去了，
于是 Python 返回 `None`，FastAPI 把它序列化成了 **`null`**。

| 同一个 `for ... return it` 函数 | 不 `raise` 时恰好没找到 | 客户端看到 |
|---|---|---|
| `/loose`（底下还有一句 `return {"error": ...}`） | 撞上那句 `return` | **200** + 一段 error |
| `/strict`（底下什么都没有） | 函数自然结束 → `None` | **200** + `null` |

两种都是 200，**前端都只能写 `if (!data || data.error)` 去猜**。框架不是在你的函数里等一个返回值，
它是在你的函数**抛出异常**的时候才有事可做。

### ⑥ 对上

**第 2 条**：`/loose/99` 回 **200**，而且带的是最后那句 `return`。
`items` 里没有 id=99，循环走完，`HTTPException(...)` 空转一行，然后撞上下一句 `return {"error": ...}`。

**第 5 条**：`detail` 可以给 dict，框架原样塞进 `{"detail": ...}` 里。
想把「哪个 id、有哪些可用」一次给全，就给 dict，别拆成多个键往顶层塞。

**第 6 条**：`418` 这种冷门码框架照收（`status_code` 不做合法性审查）。
但**能被前端理解的码是有限的几个**：今天你只需要 `400`（你这请求不对）、`404`（没这东西）、`422`（框架自己发的）、`500`（意外）。

**第 7 条**：`/strict/abc` 是 **422**，不是 404，而且 `{"detail": [...]}` 是**数组**。
两条原因叠在一起：`item_id: int` 是路径参数，它的校验发生在**进函数之前**（Day 4 第二节那条：`item_id: int` 写下的瞬间，框架在你进函数之前就已经按 `int` 试过一遍了），
所以你的 `raise` 根本没机会执行。
**记一句话**：`422` 是框架发的，长得和 `HTTPException` 完全不同——它是数组，你的是字符串（或 dict）。第四节会让你亲手确认这条边界。

### ① 建文件

### ⑤ 一句话

`return` 决定**响应体**，装饰器决定**正常时的状态码**，`raise` 决定**出事时的状态码**。三者互不干涉，出事时 `raise` 优先。

## 四、`@app.exception_handler`：把框架那个 `except` 换成你的

第二节里 `raise HTTPException` 之后，是**框架**替你 `except` 的，它固定回 `{"detail": ...}`。
这一节你要干的事：把那个「替你 except」接管过来，改成你自己的形状。

### ① 建文件

```bash
cd stage1/day006_fastapi_advanced
cat > code/python/04_handler.py <<'PY'
from fastapi import FastAPI, HTTPException, Request
from fastapi.responses import JSONResponse

app = FastAPI()


@app.get("/four/{item_id}")
def read_four(item_id: int):
    if item_id > 2:
        raise HTTPException(status_code=404, detail="没有这个 id")
    return {"id": item_id}


@app.post("/need_body")
def need_body(payload: dict):
    return {"收到了": payload["name"]}


@app.get("/boom")
def boom():
    return 1 / 0


@app.exception_handler(HTTPException)
def on_http(request: Request, exc: HTTPException):
    print("[handler-1] 接管 HTTPException，状态码是", exc.status_code)
    return JSONResponse(
        status_code=exc.status_code,
        content={"code": exc.status_code, "msg": exc.detail, "path": request.url.path},
    )


@app.exception_handler(Exception)
def on_other(request: Request, exc: Exception):
    print("[handler-2] 接管意外，类型是", type(exc).__name__)
    return JSONResponse(status_code=500, content={"code": 500, "msg": "服务器内部错误"})
PY
```

两个新面孔：

| 写法 | 是什么 |
|---|---|
| `Request` | 框架把「这一次请求」整个对象交给你，`request.url.path` 就是当前路径 |
| `JSONResponse(status_code=..., content=...)` | 一句话直接生成一个 JSON 响应，**状态码你说了算**（`return {...}` 做不到这件事） |

还有第一节的两条原理在这里正式上岗：
`@app.exception_handler(HTTPException)` 的意思是「**框架去 `except HTTPException` 的时候，别按默认来，跑我这个函数**」；
`@app.exception_handler(Exception)` 是「**凡是 `Exception` 这个范围内的，全都跑我**」——第一节的第 6 条说了，`Exception` 是个范围。

④ 里你看到了：422 谁都不印。现在亲手把它接管过来（第三节说的那句「422 是框架自己发的」，这一步就是它的证据）。

### ⑦ 对上

**第 2 条**：`{"code":404,"msg":"没有这个 id","path":"/four/9"}`。
`detail` 改名成 `msg`、状态码从 `exc.status_code` 拿、`path` 从 `request.url.path` 拿——**形状从此归你管**，前端只需要认一套 `code` / `msg`。

**第 4 条和第 6 条**：一句 `raise` 都没写，500 也变成了你的形状。
`payload["name"]` 缺键 → `KeyError`；`1 / 0` → `ZeroDivisionError`。你没写 `except`，但 `@app.exception_handler(Exception)` 就是框架替你写的那个 `except`，它把这一整类全接管了。**这就是第一节第 6 条「`Exception` 是个范围」在 HTTP 世界里的样子。**

**第 5 条**：422 不是 `HTTPException`（它是 `RequestValidationError`），也不是从你函数里冒出来的意外，
所以两个处理器都轮不到它。为什么轮不到？因为框架比你近——422 在**离端点更近的一层**就已经被框架自带的处理器变成响应了，压根没往外冒。**你能接管的，只有冒到你这一层的东西。**

**`/boom` 那个 500**：第三节洞表里「意外一律 500」这一条，从今天起形状统一了，但**状态码仍然是 500**——
`on_other` 里写死了 `status_code=500`。这是对的：**你替不了的**。「某个键没取到」到底是 400 还是 500，只有你在那个函数里才知道，这件事只能回到端点里 `raise HTTPException` 解决。

### ⑧ 顺手记两条

1. **两个处理器都写在端点函数的后面，照样生效。** 异常处理器不是「排队等执行」的代码，是**注册进一张表**；请求来的时候框架查表，表里有没有跟「谁写在前面」无关。这和第三节 `status_code=` 那种「写在装饰器里就算数」是同一个道理。
2. **它们是同步 `def`，不是 `async def`，一样能用。** 今天这种「拿现成的值拼个 dict 回出去」的活儿不需要 `await`，写法上反而更省事。但你要是想在处理器里 `await` 什么，就得改成 `async def`——今天不需要。

## 六、`@app.middleware("http")`：每个请求都过它，但崩掉的请求只过一半

### ① 建文件

```bash
cd stage1/day006_fastapi_advanced
cat > code/python/06_middleware.py <<'PY'
import time

from fastapi import FastAPI, HTTPException, Request

app = FastAPI()


@app.middleware("http")
async def log_it(request: Request, call_next):
    start = time.perf_counter()
    print("[A] 进来了：", request.method, request.url.path)
    response = await call_next(request)
    cost = time.perf_counter() - start
    print("[B] 出去了：状态", response.status_code, "耗时", round(cost, 4))
    response.headers["X-Process-Time"] = str(round(cost, 4))
    return response


@app.get("/hello")
def hello():
    print("[C] 端点函数体正在执行")
    return {"msg": "hi"}


@app.get("/bad")
def bad():
    print("[D] 端点里准备 raise HTTPException")
    raise HTTPException(status_code=404, detail="没有这个")


@app.get("/crash")

    print("[E] 端点里准备 1 / 0")
    return 1 / 0

```

读这个文件只需要接受一件事：**`call_next(request)` 就是「把请求交给后面所有东西，然后把响应拿回来」**。
它下面那三行（第 13、14、15 行）不是「请求处理时」跑的，是**响应往回走的时候**跑的。
所以这个函数被劈成了两半：`call_next` 之前是「进」，之后是「出」。中间夹着你的整个端点。

`await` 在这里是**必须的**（`call_next` 是个异步动作），所以这个函数只能写 `async def`。这是今天唯一一个 `async def`，其余全是同步 `def`。

两个不是新东西的东西：`time.perf_counter()` 就是 **Day 3 那把秒表**（「读一下现在几秒」），`round(…, 4)` 也是那天的；
但这里多了一层 `str()`——因为**响应头的值只能是字符串**。我直接塞过那个数：客户端 `Internal Server Error [500]`，
终端里 `AttributeError: 'float' object has no attribute 'encode'`（崩在 `starlette/datastructures.py`，和五 ④ 那个 `KeyError` 是同一个文件）。

## 七、`Depends()`：把「每个接口都要解析一遍」的东西抽成一个函数

第六节的中间件在**所有**请求前后做事。这一节反过来：只对**声明了它的**端点做事。

### ① 建文件

```bash
cd stage1/day006_fastapi_advanced
cat > code/python/07_depends.py <<'PY'
from fastapi import Depends, FastAPI, HTTPException

app = FastAPI()


def pagination(page: int = 1, size: int = 3):
    if size > 10:
        raise HTTPException(status_code=400, detail="size 最大 10")
    return {"page": page, "size": size, "skip": (page - 1) * size}


names = ["pen", "cap", "bag", "cup", "key", "box", "fan", "rug"]


@app.get("/names")
def list_names(pg=Depends(pagination)):
    print("[端点] list_names 函数体在跑")
    picked = []
    n = 0
    for name in names:
        if n >= pg["skip"]:
            if len(picked) < pg["size"]:
                picked.append(name)
        n = n + 1
    return {
        "页码": pg["page"],
        "每页": pg["size"],
        "跳过": pg["skip"],
        "这一页": picked,
        "总数": len(names),
    }


@app.get("/names/count")
def count_names(pg=Depends(pagination)):
    return {"页码": pg["page"], "这页准备给几个": pg["size"]}
PY
```

三段新东西，一段一段认：

| 段 | 是什么 |
|---|---|
| `def pagination(page: int = 1, size: int = 3)` | **一个普通函数**，你自己也能 `pagination(2, 5)` 调它。它不知道 FastAPI 的存在，唯一的「框架味」是里面 `raise HTTPException` |
| `pg=Depends(pagination)` | 「这个端点函数需要 `pagination` 的结果，请你（框架）在调我之前先把它准备好，塞给 `pg`」 |
| `for name in names: ...` 那七行 | 昨天的老朋友。今天仍然**不用切片**（`names[a:b]` 没教过），所以用 `n` 数下标、`len(picked)` 数够没够 |

**注意 `pg=Depends(pagination)` 里没有冒号类型注解**——`pg` 拿到的是 `pagination` 的**返回值**（那个 dict）。
它和 `min_price: int = 0` 那种「有注解、值从 URL 来」的参数不是一回事，④ 和 ⑤ 会把这条差别照出来。

### ⑥ 手工实验：一处默认值的取舍，和一对括号

**实验一**：把 `def pagination(page: int = 1, size: int = 3):` 改成 `def pagination(page: int, size: int = 3):`（去掉 `page` 的默认值），重启，打两条：

```bash
curl -s -w ' [%{http_code}]\n' http://127.0.0.1:8767/names
curl -s -w ' [%{http_code}]\n' 'http://127.0.0.1:8767/names?page=2'
```

```text
{"detail":[{"type":"missing","loc":["query","page"],"msg":"Field required","input":null}]} [422]
{"页码":2,"每页":3,"跳过":3,"这一页":["cup","key","box"],"总数":8} [200]
```

依赖函数里一个不起眼的 `= 1`，直接决定了这个端点**能不能不带参数访问**。
`page: int = 1` → 文档里 `required: false`；写成 `page: int` → 变成**必填**，不带给 422。**④ 里那个 422 的形状在这里再出现一次**，一模一样。
（`跳过 3` 是对的：`page=2, size=3` → `skip = (2-1)*3 = 3`，从下标 3 开始给 3 个 → `cup, key, box`。）

**实验二**：把 `def list_names(pg=Depends(pagination)):` 改成 `pg=Depends(pagination())`——**多了两个括号**，也就是「先把函数调用掉，把结果给 Depends」。重启：

```text
--- 终端 A（服务根本没起来）
  File ".../inspect.py", line 2526, in _signature_from_callable
    raise TypeError('{!r} is not a callable object'.format(obj))
TypeError: {'page': 1, 'size': 3, 'skip': 0} is not a callable object
```

`pagination()` 会**立刻执行一次**并交回一个 dict，于是框架拿到 dict 当成函数去读它的签名，读不出来。
**注意这次错的是启动阶段，不是请求阶段**：`Depends` 后面写的是**函数本身，不带括号**，和装饰器那两节一样——「交给框架，不是现在调用」。
（而且这个 dict 里的值是 `size: 3`——那是 `pagination` 定义里的默认值，跟 URL 再没半点关系，请求里传什么都不管用了。）

两个实验都改回原样。

### ⑦ 对上

**依赖的顺序**：请求进来 → 框架解析参数 → 先跑依赖（含它自己的参数校验）→ 依赖的返回值塞给 `pg` → 才跑你的函数体。
所以**依赖是端点前面的一道关卡**，它 `raise` 你就进不来。这一句在第八节的 `app.py` 里会直接兑现：`?size=99` 那个 400 不是端点给的。

**今天为什么值得为分页写一个函数**：`/names` 和 `/names/count` 是两个接口，都想要 `page` / `size`。
昨天的写法是两边各抄一遍 `page: int = 1, size: int = 3`，改默认值得改两处、加校验得加两处。
今天抄的东西只剩 `pg=Depends(pagination)` 一行，**校验和默认值集中在一处**。这是依赖注入唯一需要先讲清楚的理由，别的（`yield`、套依赖）今天都不需要。

### 今天第一次出现、我全部当场给了的东西

这张表就是「今天新学的」的完整清单，不多不少：

| 构件 | 第一次在哪 | 一句话 |
|---|---|---|
| `try:` / `except 类型 as err:` | 一 ① | 「出事就别往下走，跳到 except」；类型对上才跑 |
| `raise ValueError("...")` | 一 ① | 制造并扔出去；**不写 `raise` 等于什么都没发生** |
| 裸 `raise`（`except` 里那一个词） | 六 ⑤ | 看一眼，原样交上去 |
| `except Exception` 是**范围** | 一 ③ 第 6 条 | `ValueError`、`KeyError`、`TypeError` 全在里面；写窄一点才抓得住具体的 |
| `HTTPException(status_code=, detail=)` | 二 ① | 唯一一个「框架听得懂」的异常 |
| `status_code=201`（装饰器参数） | 三 ① | 只管正常时；`raise` 一响它就输 |
| `@app.exception_handler(类型)` | 四 ① | 把框架替你写的那个 `except` 换成你的；**注册进表，不看位置** |
| `Request` | 四 ①（用在处理器）、五 ①（自己用） | **按注解认参数，不按名字**（五 ⑤ 验过） |
| `JSONResponse(status_code=, content=)` | 四 ① | 处理器里**必须**用它，`return dict` 会崩在框架里（四 ⑤） |
| `@app.middleware("http")` + `call_next` | 六 ① | 一个函数劈两半：`call_next` 前是进、后是出 |
| `response.headers["..."] = "..."` | 六 ① | 往响应头里加一个自己的键；崩掉的请求加不上（六 ③ 那个 `0`） |
| `Depends(函数名)` | 七 ① | 交给框架的必须是**函数本身**，带括号服务起不来（七 ⑥） |

**只有一件东西我用了但没教**：`async def` / `await` 本身。
Day 3 你写过它，但那节讲的是「事件循环为什么需要 `await`」，今天**只有中间件那一个函数**用了 `async def`，
而它的原因是「`call_next` 是个异步动作，框架要求你 `await` 它」——**这句话是给结论，不是讲原理**。
今天你只需要接受一条：中间件函数写 `async def`，里面等 `call_next` 时写 `await`；其余函数一律同步 `def`。
