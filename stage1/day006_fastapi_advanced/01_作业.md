## 第 1 题 · 先排序，再运行

**做什么**：**不要运行代码**。下面这个 app，把 `GET /ok` 会产生的 9 条记录**按执行顺序排列**。

```python
TRACE: list[str] = []

@app.middleware("http")
async def mw1(request, call_next):
    TRACE.append("mw1-in"); r = await call_next(request); TRACE.append("mw1-out"); return r

@app.middleware("http")
async def mw2(request, call_next):
    TRACE.append("mw2-in"); r = await call_next(request); TRACE.append("mw2-out"); return r

def dep_a():
    TRACE.append("dep_a"); return "a"

def dep_b(a=Depends(dep_a)):
    TRACE.append("dep_b"); return "b"

def dep_resource():
    TRACE.append("acquire")
    try:
        yield "res"
    finally:
        TRACE.append("release")

@app.get("/ok")
async def ok(b=Depends(dep_b), res=Depends(dep_resource)):
    TRACE.append("handler"); return {"b": b, "res": res}
```

9 条记录是：`mw1-in` `mw1-out` `mw2-in` `mw2-out` `dep_a` `dep_b` `acquire` `handler` `release`

你的排序：

```
1.
2.
3.
4.
5.
6.
7.
8.
9.
```

**验收结果**（本机实测）：

```
['mw2-in', 'mw1-in', 'dep_a', 'dep_b', 'acquire', 'handler', 'mw1-out', 'mw2-out', 'release']
```

**过关标准：9 个位置至少对 7 个，且这三条必须全对**：

1. `mw2-in` 在 `mw1-in` **前面**（后注册的中间件在外层）
2. `dep_a` 在 `dep_b` **前面**（依赖拓扑序，与参数列表顺序无关）
3. `release` 在**最后**，排在 `mw2-out` 之后

第 3 条是今天最反直觉的一条。如果你把它排在 `handler` 后面紧跟着，
说明你以为 `yield` 依赖像 `with` 语句一样在函数返回时就退出——它不是。

## 第 3 题 · 亲手验证「后注册的在外层」

**做什么**：把 `pipeline.py` 里 `mw1` 和 `mw2` 的**整块定义互换位置**
（`mw2` 写在上面，`mw1` 写在下面），重跑。

**验收结果**：四条 TRACE 里所有中间件记录**全部翻转**，变成：

```
/ok   ['mw1-in', 'mw2-in', 'dep_a', ..., 'mw2-out', 'mw1-out', 'release']
```

即 `mw1-in` 跑到了最前面。**非中间件的记录（`dep_a` `dep_b` `acquire` `handler` `release`）位置完全不变。**

这说明两件事：

1. 中间件的内外层**只由定义顺序决定**，和函数名无关（名字里的 1、2 没有任何语义）
2. 中间件链和依赖链是**两套独立的顺序规则**，互不影响

## 第 5 题 · 费曼任务：4 句话

**做什么**：向同事解释——**为什么 `yield` 依赖的 `finally` 在正常请求和异常请求里
执行时机不同，写代码时该怎么应对。不超过 4 句。**

```
1.
2.
3.
4.
```

**验收结果**——对照这 4 条：

1. 说清 `finally` **两条路径都会执行**，可靠性没问题
2. 说清正常路径下 `release` 在**响应发出之后**（排在中间件 out 后面）
3. 说清异常路径下 `release` 在**异常处理器之前**
4. 给出可操作的结论：**中间件里不要假设资源已释放；异常处理器里可以**

**自测**：同事反问「那我在中间件里能不能读到清理后的状态」，你要能立刻答：**不能**。
再追问「那我的清理代码很慢，会不会拖慢用户感知的响应时间」，你要能答：
**不会拖慢响应**（响应已经发出去了），**但会占用 worker**，并发能力照样下降。
