## 一句话需求

给它一个问题，它自己去多个来源取证、交叉核对、写成一份**每条结论都挂着来源**的报告，
而报告入库前必须过人工审批。

## 为什么题目是"技术调研"而不是别的

调研对象限定为**工程技术问题**（框架选型、机制原理、方案对比），不是行业/财经/医疗。两个硬理由：

1. **你是这份报告的合格评分人。** 研究 Agent 最大的坑是"产出看起来对"。让你无法判断对错的领域，
   你的 evaluator 环节就退化成了走过场。技术调研正好：你知道答案，所以自评语循环是真的在干活。
2. 你需要用它解决自己的真实问题——学 LangGraph 过程中本来就有几十个待查问题，直接拿它们当输入。

这道题的弱点也摆在这里：**通用研究 Agent 是烂大街的作品集题目**。所以本项目靠两件事挣回区分度——
FR-21 的引用可追溯、FR-22 的模糊问题反问。这两条做到了，面试官会知道你不是照抄 tutorial。

## 场景示例

输入：「LangGraph 的 checkpointer 支持哪些后端，各自的适用场景和性能代价是什么？」

系统要能：

1. 判断问题类型（事实查询 / 方案对比 / 实操教程 / 过于模糊），走不同处理路径
2. 把问题拆成若干子查询（子查询数量由问题决定，不是写死的）
3. 并行执行子查询，各自调用工具取证
4. **交叉核对**：同一结论有几个来源支持
5. 汇总成带引用的报告草稿
6. 自评草稿是否真正回答了原问题，不合格就带着自己的批评重写（有上限）
7. 入库前中断，等人 approve / edit / reject
8. 全程流式可观察；历史可回放、可分叉；跨会话记住用户偏好

## 工具清单（就这 4 个，别自己加）

| 工具 | 读写 | 要求 |
|---|---|---|
| `local_docs` | 只读 | 在 `fixtures/docs/*.md` 里做关键词检索并返回命中片段（本地、离线、稳定） |
| `web_fetch` | 只读 | 抓免费公开页面（官方文档 / Wikipedia / arXiv 任选）。**注入 5% 随机失败**，用于验证 retry |
| `rss_read` | 只读 | 读一个 RSS/Atom 源的最新条目 |
| `save_report` | **写入** | 把定稿报告写进 `reports/` 并在 sqlite 里建索引。**全项目唯一需要审批的操作** |

缓存要求：`web_fetch` 与 `rss_read` 的结果按 URL 缓存到本地，重复提问不发请求。

## 功能需求

| 编号 | 要求 | 对应课程 |
|---|---|---|
| FR-1 | 状态用 `TypedDict` + `Annotated` 定义；**至少 2 个键使用 reducer**，并说明为什么这两个键必须追加而非覆盖 | U1-2 / U1-3 |
| FR-2 | 问题分类走**条件边**（或 `Command`），四类各有一条独立路径；分类由 LLM 输出，不允许用关键词 if-else 假装分类 | U2-1 / U2-5 |
| FR-3 | 子查询用 `Send` **动态扇出**：拆出 3 个子查询和 7 个子查询时，图结构不需修改 | U2-4 |
| FR-4 | 并行分支有**汇聚节点**，汇聚结果完整无丢失（用测试钉住） | U2-3 |
| FR-5 | `web_fetch` 的随机失败由节点上的 `RetryPolicy` 兜住；重试次数可配置并有日志证据 | U2-7 |
| FR-6 | `web_fetch` / `rss_read` 结果**被缓存**；同一问题第二次运行不发请求（日志证明） | U2-7 |
| FR-7 | 自评-重写构成一个**循环**，上限 3 次；达上限时返回部分结果而非抛异常 | U2-6 |
| FR-8 | checkpointer 用 **SQLite**；`thread_id` 由会话决定，不同会话历史互不污染 | U3-1 / U3-2 |
| FR-9 | 提供**回放**能力：给定 thread_id，能列出全部中间状态，并能从任意一步重新执行 | U3-3 / U3-4 |
| FR-10 | 用户偏好（如「只看官方文档」「回答控制在 500 字内」）存 **store**；换一个全新 `thread_id` 仍然生效 | U3-5 |
| FR-11 | 长对话有**上下文裁剪**策略；连续 20 轮后 prompt token 不上涨（打印每轮长度证明） | U3-6 |
| FR-12 | `ToolNode` 版与手写 `tool_calls` 处理版**各实现一版**（可切换），工具行为等价 | U4-3 / U4-4 |
| FR-13 | 只对 `save_report` 做人工审批；三个只读工具不中断 | U4-5 |
| FR-14 | 审批支持 **approve / edit / reject** 三态；edit 能证明原文被替换；reject 走一条明确的善后路径（不能直接 END 丢结果） | U4-2 |
| FR-15 | **中断状态持久化**：进程被 kill 后重启，凭 thread_id 能继续审批并跑完（必须真做，见 V-7） | U4-6 |
| FR-16 | 取证环节**封装为子图**，作为父图一个节点；父子图状态共享规则在测试里钉住 | U5-3 |
| FR-17 | 提供 **SSE / 流式**接口，外层能看到子图内 LLM 的逐 token 输出 | U5-1 / U5-2 / U5-4 |
| FR-18 | 五种 Agent 模式（prompt chaining / 并行 / 路由 / orchestrator-worker / evaluator-optimizer）**在本项目中各有真实用处**，README 里指出每处属于哪种 | U5-6 |
| FR-19 | 一个极简 Web 界面（一页 HTML，**不超过 200 行**）能提问、看进度、做审批 | 你的强项 |
| FR-20 | 能以 `langgraph dev` 或 FastAPI 任一种方式常驻启动，并给出你实际用的那条命令 | 课件 §9 |
| FR-21 | **引用可追溯**：报告里每条结论挂 `source_id`；末尾列来源清单（URL + 抓取时间）；只有 1 个来源支持的结论标 `⚠ 单一来源` | U1-3 / U2-3 |
| FR-22 | **模糊问题反问**：判定为"过于模糊"时不许硬答，走一条向用户提问的路径并等回复（这是 `interrupt` 的第二种用法） | U4-1 |

## 明确的"不做"边界

超出即过度工程，扣分不加分：

- 不做用户系统、鉴权、多租户
- 不做向量库 / embedding / RAG（课程没教，那是下一门课；本项目靠关键词检索 + LLM 判断）
- 不做爬虫反爬对抗、不做分布式抓取、不做限流调度
- 不做前端路由、状态管理库、组件库、样式打磨
- 不做 K8s、不做 CI/CD；**只有为了部署演示才允许一个 Dockerfile**
- 不做多个模型的对比实验；一个模型跑到底
- 一个进程，不拆微服务

### 自问题（10 题，答不出退回对应单元）

1. 为什么并行分支必须配 reducer？给出你不配时观察到的**具体**现象，不是"会覆盖"这种背下来的话。（U1-3）
2. 你的图里哪个节点返回值最大？为什么节点不该返回整个 state？（U1-4）
3. `Send` 和"加一条边"的本质区别是什么？（U2-4）
4. 你的循环靠什么退出？如果没有这个退出条件，报错长什么样？（U2-6）
5. `thread_id` 和 store 的 namespace，分别在什么场景下你会后悔用错了对方？（U3-2 / U3-5）
6. 中断发生时，磁盘上那个 `.sqlite` 文件里存了什么？（U4-6）
7. 模型"调用工具"这个说法哪里不准确？你的代码里谁真正执行了工具？（U4-3）
8. 你为什么把取证做成子图而不是一个普通函数？做成函数会丢什么？（U5-3）
9. 你的流式接口用的哪种 stream mode？换成 `values` 会发生什么？（U5-1）
10. 五种模式里，你的项目**没用**上哪一种？没用上是场景不需要，还是你不会用？（U5-6）

### 从零题（出师）

换一个完全无关的领域（工单分诊 / 合同审查 / 客服路由，任选），**不看任何资料**，4–6 小时做出：
路由 + 动态扇出 + 一个中断审批 + SQLite 记忆 + 流式。
判定只看两条：拓扑图你能不能自己画出来；每个 reducer 你能不能说出防的是什么错。

## 最容易被蒙混过去的 6 个点

自查这 6 条，它们是"看起来完成了"最常见的成因：

1. **用 if-else 代替条件边** —— 图里根本没有分支，`draw_mermaid()` 导出拓扑一看便知
2. **checkpointer 一直用内存版** —— 装了 SQLite 但从未跨进程验证（见 V-7）
3. **审批是在同一进程里 continue 的** —— 那样不需要持久化，等于没学 U4-6
4. **工具是 Python 直接调的** —— 模型从未生成 `tool_calls`，那是普通函数调用不是 tool calling
5. **流式是把最终结果一次性 print** —— 没有真 stream，token 级穿透需要 U5-4 的做法
6. **报告的引用是模型编的** —— LLM 会凭空造 URL。V-16 就是用请求日志反查引用集合，多出来的引用一律算失败
